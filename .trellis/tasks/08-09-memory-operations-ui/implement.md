## Verification and review policy

Run affected tests/types/lint and required package checks at the integrated change boundary, with
targeted regressions for real fixes. Do not rerun unchanged accepted suites after every small edit.

Use one independent design challenge for a material architecture/persistence/security change, then
one consolidated review of the complete increment. Routine edits, inventory packets and each test
execution do not each need another independent reviewer. Findings require verified reachability and
impact; fix the actual defect rather than expanding the scope automatically.

Retain one concise result record per meaningful run with input/build identity, command, expected and
observed behavior, relevant failure evidence and owned resource disposition. No new evidence-packaging
or hash-release framework is part of this plan. Keep one heavy runner and at most two Vitest workers
where the current resource limits require it.
