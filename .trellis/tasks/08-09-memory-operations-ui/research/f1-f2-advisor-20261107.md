## Recommended final design

**Native F1 — two production files**

- In `engine/taki_compatibility.py`, retain the uncached inspector and separate reusable schema-support results from live observations.
- In `engine/memory_engine.py`, own a lazy cache by effective authenticated schema and sorted Alembic revision set. Backend/tenant lifetime is implicit in the engine.
- Authenticate every entry. Recheck cheap descriptors and read current lineage/revisions using one pool acquisition. Return the **live lineage** with cached support.
- Cache only fully successful inspections under the revision actually observed. Missing/unreadable revision metadata falls back to the existing inspector; it must not introduce a new refusal.
- Clear at engine teardown. Leave `extensions/context.py`, maintenance checks and transition transaction checks unchanged. No generation, TTL, single-flight or failure callback.
- Route the listed engine application/native-result/manifest **and journal/snapshot** callers through this owner. Keep independent administrative inspectors uncached.

**Core F2 — six production files**

1. `hindsight-application-capability.ts`: retain `admitHindsightApplication` as the fresh path; add a small evidence-aware resolver. Missing evidence → existing admission. Existing evidence → authenticated compatibility read, current capability/lineage checks and whole-manifest comparison. Equal → reuse; changed → fresh admission or the existing refusal.
2. `hindsight-runtime-state.ts`: bind the resolver to `(epoch, configFingerprint)` and the existing repository. Guard before work and after awaits; save only new/changed admitted evidence. Preserve private-template execution’s existing fresh/nonpublishing path.
3. `hindsight-application-sync-runner.ts`: accept the optional resolver; standalone construction retains fresh admission.
4. `hindsight-memory-provider-context.ts`: expose an optional guarded admitted-evidence reader. Preserve existing capability snapshots and degraded behavior.
5. `hindsight-memory-reflect.ts`: after successful synchronization, consume that evidence and independently require guarded Reflect. Keep the standalone/private fallback.
6. `hindsight-pending-recovery-runner.ts`: after the first successful D77 pull, consume admitted evidence for G1 support. Preserve the legacy probe when no reader is supplied. A failed read/negotiation must throw, not become `false`.

Use existing `sameApplicationValue` for manifest comparison; no new persisted hash is necessary. The repository’s `evidence_hash` hashes identity and timestamp too, so it is not a manifest-only hash.
