1. **Acceptance map.** Map the PRD first-use criteria, the section 2 backup/transition cases (C07/C08/C10) and the
   relevant parent criteria to existing evidence. Mark each as evidenced, partial or unverified, and name the
   smallest run that closes each gap. Output: `acceptance-map-20261107.md`.
2. **Blocking performance.** Treat a slowdown that causes a timeout, failure or unstable result as a defect.
   - F1: cache the per-request Native compatibility manifest.
   - F2: stop Core repeating capability admission on every synchronization.
   Both come from [performance-investigation-20261106.md](performance-investigation-20261106.md). Steps: design,
   advisor challenge, implementation, focused regression, then one real E2E run before/after for timing.
   **Design decision (2026-11-07):** adopt the advisor's simplified form
   ([design](f1-f2-design-20261107.md), [advisor](f1-f2-advisor-20261107.md)).
   - F1: an engine-owned cache of fully successful schema inspections, keyed by authenticated schema and Alembic
     revision set. Authentication, cheap descriptors, live lineage and the revision read stay per request. No
     generation counter, migration hook, TTL or failure callbacks. Journal/snapshot callers use the same owner.
   - F2: on a warm sync, one live compatibility read is compared with the persisted admission evidence for
     (epoch, configuration fingerprint). Equal means reuse; a missing or changed result means the existing full
     admission. Reflect and Pending recovery reuse the evidence admitted by their sync. Explicit connection
     revalidation stays a full three-call admission. Six Core files, no client callbacks.
   - Build identity: the cache is a patch-series change under `TAKI_MEMORY_COMPATIBILITY_BUILD`. The bump is
     deliberately batched with the phase-1 baseline (D97). It is not an exemption.
   - Journey 16's 30-second backup quiescence failure is historical: journey 17 passed both backups on the first
     attempt. Its existing regression tests stay.
   - Post-chat maintenance on the 1,690-source library (P1-AA, 2026-11-08): it holds the write fence 74-88 s after
     a chat and blocks the event loop long enough to delay timers, so a backup in that window fails its first
     attempt and the curator's 60 s pass ends before publishing everything. Observe the whole window first, then
     remove proven redundant synchronous work at its owner (option B, P1-AB). Speed-only gains stay in phase 2.
3. **Large-library coarse check.** Run a copied-instance replay on the existing 1,690-source fixture after item 2.
   It only detects severe degradation; it is not a stress test.
4. **Close phase 1.** Update the usable-delivery report with build identity, results and limits. Log deferrals in
