# Phase 2 design — responsive memory maintenance and simpler execution boundaries

## 1. Outcome

**DONE — read-only design delivered; implementation and new runtime acceptance are not performed.** Recommend one Core-owned `worker_threads` worker with its own **live, read-only WAL connection** for expensive reads, decoding, integrity verification and projection preparation. Keep all SQLite mutations, current-authority admission, durable claims and Native command dispatch with the existing Core writer. Pair this with short publication admissions and foreground-first Bank work; moving CPU alone would leave foreground queueing and the long backup fence intact. ## 4. Trade-offs

- **Worker isolation costs memory and coordination.** One extra isolate/connection and bounded message copies replace main-thread CPU stalls; benefits must include total Core memory and concurrent latency, not only worker throughput. [inference]
- **More granular ownership adds currentness retries.** Main state may change while the worker reads. Reject/recompute affected targets instead of holding a long fence or granting stale authorization; very active Banks can delay review, which remains visible and durable. [inference]
- **Scheduling delays enrichment.** Neutral items remain recallable, while classification, retention refinement and background Blocks may lag until schedule/threshold. That is the intended behavior change; hiding all unreviewed memories would be an additional unapproved change. [source .trellis/spec/backend/hindsight-application-runtime.md:130] [inference]
- **Durable item saves increase small transactions but avoid repeated model work.** Reuse current work IDs/results; do not turn pass completion into an all-or-nothing model replay. Failed attempts and legitimately changed versions can still be retried. [source packages/core/src/db/hindsight-policy-work-repo.ts:92] [inference]
- **Foreground preference lowers maintenance throughput.** Backlog persists across batches; count/schedule fallback must retain fairness and cannot discard work. A strict mathematical guarantee of zero shared CPU/Native contention is not offered. [inference]
- **Targeted publication returns sooner with unrelated maintenance still outstanding.** Completion proves the receipt's exact applied artifacts and checkpoint, not all Bank enrichment or derived freshness. [source packages/core/src/memory/hindsight/hindsight-application-writer.ts:44] [source packages/core/src/memory/operations/memory-authority-status.ts:86] [inference]
- **D103 is a persisted/protocol behavior change.** It needs compatible old-row reads and coordinated producer/Home changes; cosmetic relabelling is cheaper but incorrect. D104 adds bounded user-visible waiting and does not guarantee every backup wins contention. [inference]
- **Lower Native concurrency/pools trade memory for queue latency.** Keep model identities/semantics unchanged; only adopt settings that preserve the foreground gate. New runtimes, model unloading and re-embedding are separate owner decisions. [source docs/DEPLOYMENT-RESOURCES.md:85] [inference]
