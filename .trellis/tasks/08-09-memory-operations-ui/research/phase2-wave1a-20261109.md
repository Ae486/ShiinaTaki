## 4. Trade-offs

- **Scoped memory and synchronous work:** exact decoded objects live until the read callback returns; a warm cache
  frontier can be read in one larger synchronous transaction instead of many eight-body await groups. This contracts
  repeated work but does not isolate CPU or guarantee an event-loop bound. Total memory and longest pause require the
  leader's replay. No supported corpus/body limit was reduced. [source packages/core/src/memory/hindsight/hindsight-application-bundle-loader.ts:104] [inference]
- **Explicit trusted data ports:** `decodedBody` and batched `cachedBodies` require byte-verifying owners. Their current
  production providers use the existing replica/command stores or verified bundle map; generic independent callers
  retain full validation. This adds a small internal API obligation, documented in both specs, without a TTL/global
  verdict cache or new durable store. [source packages/core/src/memory/hindsight/hindsight-application-projection.ts:22]
- **Retained full-proof cost:** full bundle, projection, publication, backup and recovery validation can still parse
  the same bytes at independent boundaries. Removing those checks would require a different proof contract; this
  assignment preserves them. [source packages/core/src/memory/hindsight/hindsight-memory-read-projection.ts:23]
- **Native/reference ownership:** no Native engine rewrite, retry owner, claim journal, fence or scheduler was added.
  The new lexical adapter is needed because the former replica API independently admitted every individual read;
  it composes existing validators and the existing prompt-capture transaction pattern. [source packages/core/src/db/hindsight-application-replica-read-snapshot.ts:12] [inference]
- **Collection behavior:** successful claims, not candidate positions, consume the existing report capacity. A failed
  claim does not drop later eligible work. The independent-review regression is fixed and covered. [source packages/core/src/memory/hindsight/hindsight-policy-curator.ts:85]
