### Memo and rollback behavior

The cheap prepared statement reads the stamp/schema token. A schema change triggers the separate full statement,
which returns a token from the same snapshot as matching trigger names, owning tables, types and exact SQL.
Only verification observed outside a transaction updates the connection's last verified schema version, because
transactional schema cookies can repeat after rollback. A cache miss rereads the token and dependencies together: it uses an existing
SQLite transaction directly, or opens its own read transaction. The result enters the memo only when no enclosing
transaction remains. Missing/altered triggers, bad current data and mismatched identities still throw.
[source packages/core/src/db/migrations/061-hindsight-runtime-identity.ts:23]
[source packages/core/src/memory/hindsight/hindsight-runtime-authority.ts:56]

The getter fixes an additional case beyond ordinary random-stamp rollback: a drop/write/recreate trigger interval
can repeat an abandoned schema cookie without changing the stamp. No transaction-derived memo is published, so
that state must be read again. The regression also corrupts a checkpoint through such an interval and proves
the actual command repository refuses before inserting a new job. Direct SQL BEGIN is tested separately.
[source packages/core/src/memory/hindsight/hindsight-runtime-identity.test.ts:91]
[source packages/core/src/memory/hindsight/hindsight-runtime-identity.test.ts:128]
