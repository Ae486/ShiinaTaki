### Question 3 — What online rebinding proves, and offline reconstruction

**Online rebinding is mechanical policy carry with live concurrency checks. It does not obtain a new semantic policy assessment.**

1. `bindHead` reads/verifies the new Native record, obtains the exact prior artifact from `head.bound_artifact`, and requires that artifact to remain the latest for its key. Because a prior policy exists, first-policy label collection is not requested. [source packages/core/src/memory/hindsight/hindsight-application-binding-collector.ts:77]
2. `rebindMemory` requires an `exact_native` prior Memory artifact. For an advancing revision it verifies namespace, Bank, object identity, forward revision and policy ownership, copies the prior body/policy, and replaces assessment with `due` targeting the new version. Policy values, policyVersion/updatedAt, provenance, original record and encoded metadata are preserved. Source-artifact references are recomputed from current bound document evidence. Same-version document-dependency invalidation also becomes assessment due. [source packages/core/src/memory/hindsight/hindsight-application-binding-context.ts:116] [source packages/core/src/memory/hindsight/hindsight-application-binding-context.ts:143] [source packages/core/src/memory/hindsight/hindsight-policy-assessment.ts:48]
3. The immutable command is `rebind_artifact` with exact `expected_artifact`, exact `expected_native`, new body reference, and the background binding actor. The writer uploads bodies and submits the durable request. [source packages/core/src/memory/hindsight/hindsight-application-binding-runner.ts:79] [source packages/core/src/memory/hindsight/hindsight-application-binding-runner.ts:123]
4. Native checks the current artifact CAS, the live head, **reloads the actual live/archived canonical payload and verifies its hash**, validates assessment target, source-reference existence/non-retirement, original-record preservation and policy-version rules. It holds the Bank/state locks, requires application/native cursor agreement, writes a new artifact revision and `bound` head, and emits an event/receipt. Core then pulls this publication before making it locally readable. [source hindsight_api/engine/application_state/commits.py:56] [source hindsight_api/engine/application_state/commits.py:144] [source hindsight_api/engine/application_state/commits.py:230] [source hindsight_api/engine/application_state/commits.py:304] [source hindsight_api/engine/application_state/commits.py:351] [source packages/core/src/memory/hindsight/hindsight-application-sync-runner.ts:138]

Offline emergency can verify captured bytes, scope, identities, artifact history, policy ownership and the snapshot's internal dependency closure. It **cannot** verify that the unreachable Native canonical row still equals the captured new version; that its latest artifact/source heads have not changed since the checkpoint; or that a new rebind command was accepted by Native and has a Native receipt. These are freshness/serialization/acknowledgment differences, not an unavailable LLM approval. Emergency already accepts unknown unseen remote changes for ordinary bound snapshots. [source hindsight_api/engine/application_state/commits.py:56] [source hindsight_api/engine/application_state/commits.py:230] [source .trellis/spec/backend/memory-transition-emergency.md:51] [inference]

An offline implementation would project the **new captured Native content with the exact prior policy**, remap canonical identities, preserve restrictions/history/source evidence, and explicitly record an emergency policy carry. It must not forge a Native `bound` artifact or receipt, overwrite the historical original record, reinterpret unresolved policy writes as successful, or substitute the prior text. Current P1-U disallows this, so it requires a deliberate rule/proof change shared by preview, admission, reconstruction, publication and restart. **Is the old policy still correct?**

- For only `revision`, `consolidated_at`, and `consolidation_failed_at` changing, with the same content, provenance dependencies and ownership, carrying policy is consistent with the existing contract. Hidden/pinned/mood/expiry/retention choices have not been semantically reevaluated by those markers. - For changed text through curation or observation merge, the old policy remains the **last known policy/restriction**, which today's online rebind deliberately preserves. Its semantic suitability for the new text is UNKNOWN until assessment. The code marks assessment due; it does not claim a previous model assessment certified the new text.
