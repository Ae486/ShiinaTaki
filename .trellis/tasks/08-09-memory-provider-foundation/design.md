# Canonical Memory Provider Foundation - Technical Design

> Scope: Batch 1 only. This design creates a dormant structured Local Provider and provider-neutral contracts. It
> does not migrate a workspace, connect to Hindsight, switch production authority, or wire automatic recall.

## 1. Context and Problem

The shipped memory engine has one concrete composition: Markdown files are authoritative, SQLite/FTS is a rebuildable
projection, model tools are `memory_write`/`memory_search`/`memory_archive`, and post-turn maintenance is tied directly
to that engine. Hindsight integration needs a different shape:

- one explicit Memory Authority;
- Hindsight-aligned logical records rather than Markdown documents as runtime state;
- a complete Local Provider when Hindsight is absent;
- one async contract that also tolerates a later network provider;
- Taki policy kept separate from provider-generic semantic memory;
- reversible, revision-checked mutation and structured tool errors.

Batch 1 establishes that shape without changing a production workspace. The current seams and line-level evidence are
recorded in `research/current-local-memory-seams.md`.

## 2. Goals and Non-goals

### Goals

1. Freeze strict shared canonical schemas aligned with Hindsight's public Bank/document/memory-unit/mental-model/
   directive model and Slice 0 revision contract.
2. Persist a Local Authority Epoch, canonical logical records, Taki policy projections, and idempotent write receipts
   in Core SQLite.
3. Implement a fully usable Local Provider with retain, sparse recall, edit, invalidate, restore, and reclassify.
4. Keep FTS5/BM25 always available and rebuildable; reserve an optional asynchronous vector seam.
5. Make every provider/coordinator call Promise-based and return one validated capability/error envelope.
6. Replace canonical Memory Block runtime files with structured Core-owned policy documents that never enter FTS.
7. Build isolated Hindsight-aligned model tools while keeping the existing production tool/runtime path unchanged.

### Non-goals

- Hindsight network code, secrets, compatibility handshake, or templates.
- Migration, conversion, dry-run, activation, dual-write, or legacy aliases.
- Replica journal/snapshot/checkpoint, pending outbox, degraded recovery, or authority switching.
- Automatic foreground recall, Write Gate rewiring, provider-specific maintenance, or UI.
- Embedding calls, a vector dependency, hybrid calibration, fact extraction, observations, graphs, or mental-model
  generation.

## 3. Ownership Boundaries

| Concern | Owner in Batch 1 | Boundary |
| --- | --- | --- |
| Canonical schemas and envelopes | `@taki/shared` | No provider-private SQL or transport types. |
| Authority epoch and canonical persistence | Core SQLite repositories | Single Core writer; no filesystem authority. |
| Local retain/mutate/recall behavior | Canonical Local Provider | Async facade over synchronous Core transactions. |
| Active-provider selection and error normalization | Memory Coordinator | Exactly one persisted authority; no fallback. |
| Taki layer/visibility/retention projection | Core memory policy adapter | Separate from provider-generic fact meaning. |
| Memory Block content | Core structured block repository | Taki policy document, not a fact and never FTS-indexed. |
| FTS and optional vectors | Rebuildable projections | Never authoritative. Sparse is mandatory; vector is optional. |
| Legacy Markdown memory | Existing memory engine | Remains production authority until Batch 2. No dual-write. |
| Hindsight logical contract | Later Hindsight Provider | Batch 1 aligns schemas but performs no HTTP operation. |

## 4. Canonical Shared Contracts

Implementation target: responsibility-split `packages/shared/src/memory-provider-*-schema.ts` modules, exported
explicitly from `packages/shared/src/index.ts`. Keep domain records, operation payloads, and result/error envelopes in
separate files so every production file remains below the 300-line cap. All objects use `z.strictObject`, bounded
strings/arrays/maps, ISO timestamps, and opaque IDs. Unknown fields fail validation rather than being silently stripped.

### 4.1 Common identities

```ts
type MemoryProviderId = string;       // "local" now; "hindsight" later
type AuthorityEpochId = string;       // UUID
type MemoryBankId = string;           // Taki-stable opaque ID
type MemoryDocumentId = string;       // Hindsight document_id equivalent
type MemoryUnitId = string;           // Hindsight memory_id equivalent
type MemoryRequestId = string;        // UUID, generated by runtime/coordinator
type MemoryRevision = number;         // integer >= 1
```

IDs are never derived from raw memory text. Batch 2 may derive deterministic document IDs from normalized legacy
source identity, but that policy is outside this task.

### 4.2 Authority epoch

```ts
interface MemoryAuthorityEpoch {
  epochId: AuthorityEpochId;
  providerId: MemoryProviderId;
  providerLineageId: string;
  mode: "authority";
  status: "active" | "closed";
  predecessorEpochId: AuthorityEpochId | null;
  startedAt: string;
  endedAt: string | null;
  reason: "initial-local" | "planned-switch" | "emergency-takeover";
}
```

Only `providerId="local"`, `status="active"`, and `reason="initial-local"` are creatable in Batch 1. Local generates
and persists an opaque UUID provider lineage when the first epoch is initialized. The field aligns with the accepted
Hindsight compatibility manifest's provider lineage and distinguishes provider instances without importing provider
storage details. The broader vocabulary prevents later schema breakage but does not authorize later state transitions.

### 4.3 Canonical Bank

```ts
type MemoryBankScope =
  | { kind: "global"; characterId: null }
  | { kind: "character"; characterId: string };

interface CanonicalMemoryBank {
  authorityEpochId: AuthorityEpochId;
  bankId: MemoryBankId;

  updatedAt: string;

```

`disposition`, `mission`, and `config` match the public Hindsight Bank logical payload. Scope is Taki-owned. The
external Hindsight Bank ID mapping belongs to the later connection/cutover batches.

### 4.4 Canonical source document and provenance

```ts
interface MemoryProvenance {
  actor: "user" | "agent" | "system" | "provider";
  origin: "explicit-user" | "explicit-agent" | "auto-gate" | "machine-observed" | "legacy-import" | "provider-derived";
  characterId: string | null;
  timelineFromSeq: number | null;
  timelineToSeq: number | null;
  capturedAt: string;
  sanitized: true;
  sourceRef: string | null; // opaque reference only; never a filesystem path in model output
}

interface CanonicalMemorySource {
  authorityEpochId: AuthorityEpochId;
  bankId: MemoryBankId;
  documentId: MemoryDocumentId;
  contentHash: string | null;
  retainedText: string | null;
  context: string | null;
  tags: string[];
  metadata: Record<string, JsonValue>;
  observationScopes: "shared" | string[][] | null;
  provenance: MemoryProvenance;
  revision: MemoryRevision;
  createdAt: string;
  updatedAt: string;
}
```

`documentId`, hash, tags, metadata, observation scopes, and timestamps align with Hindsight's public document payload.
`retainedText` is a Taki extension: Local stores the sanitized retained span, while a later Hindsight replica may set it
to `null` because the accepted logical journal intentionally excludes private raw retain text.

### 4.5 Canonical memory unit

```ts
interface CanonicalMemoryUnit {
  authorityEpochId: AuthorityEpochId;
  bankId: MemoryBankId;
  memoryId: MemoryUnitId;
  documentId: MemoryDocumentId | null;
  chunkId: string | null;
  text: string;
  context: string | null;
  factType: "world" | "experience" | "observation";
  state: "valid" | "invalidated";
  revision: MemoryRevision;
  tags: string[];
  metadata: Record<string, JsonValue>;
  entities: string[];
  sourceMemoryIds: MemoryUnitId[];
  observationScopes: "shared" | string[][] | null;
  eventDate: string | null;
  occurredStart: string | null;
  occurredEnd: string | null;
  mentionedAt: string | null;
  createdAt: string;
  updatedAt: string;
  editedAt: string | null;
  consolidatedAt: string | null;
  consolidationFailedAt: string | null;
  invalidationReason: string | null;
  invalidatedAt: string | null;
  proofCount: number; // integer >= 1
}
```

This mirrors Slice 0 `MemoryUnitLogicalPayload`. Local retain creates one `experience` unit by default and does not
pretend to perform one-to-many extraction. `observation` is accepted for replica/derived compatibility but is not
generated by the Batch 1 Local Provider.

Lifecycle invariants:

- `valid`: `invalidatedAt` and `invalidationReason` are null;
- `invalidated`: `invalidatedAt` is non-null; reason may be null;
- restore returns to `valid`, clears invalidation fields, and increments revision;
- edit increments revision and sets `editedAt`;
- permanent deletion is not part of the provider/tool contract.

### 4.6 Derived memory

Hindsight observations remain `CanonicalMemoryUnit` records with `factType="observation"` and `sourceMemoryIds`.
The remaining public derived objects use a discriminated union:

```ts
type CanonicalDerivedPayload =
  | {
      kind: "mental_model";
      bankId: MemoryBankId;
      mentalModelId: string;
      subtype: string;
      name: string;
      sourceQuery: string | null;
      content: string | null;
      tags: string[];
      maxTokens: number | null;
      trigger: Record<string, JsonValue> | null;
      lastRefreshedAt: string | null;
      createdAt: string;
      reflectResponse: Record<string, JsonValue> | null;
      structuredContent: Record<string, JsonValue> | null;
    }
  | {
      kind: "directive";
      bankId: MemoryBankId;
      directiveId: string;
      name: string;
      content: string;
      priority: number;
      isActive: boolean;
      tags: string[];
      createdAt: string;
      updatedAt: string;
    };

interface CanonicalDerivedMemory {
  authorityEpochId: AuthorityEpochId;
  bankId: MemoryBankId;
  objectRevision: MemoryRevision;
  payload: CanonicalDerivedPayload;
}
```

The payload field names match Slice 0's `MentalModelLogicalPayload` and `DirectiveLogicalPayload`. `objectRevision`
maps the revisioned journal/snapshot envelope rather than inventing a provider payload field. The repository rejects a
row unless the outer Bank/kind/object identity agrees with the discriminated payload. Batch 1 persists and validates
these shapes but Local does not generate them or advertise semantic `reflect`.

### 4.7 Taki policy projection

```ts
type MemoryVisibility = "pinned" | "retrieved" | "mood-gated" | "hidden";

type MemoryRetention =
  | { kind: "permanent" }
  | { kind: "rolling-window"; days: number }
  | { kind: "expiring"; expiresAt: string }
  | { kind: "importance-decay"; archiveBelowImportance: number; afterDays: number };

interface TakiMemoryPolicyProjection {
  authorityEpochId: AuthorityEpochId;
  bankId: MemoryBankId;
  memoryId: MemoryUnitId;
  layerId: string; // registry ID; "unclassified" fallback
  importance: number; // integer 1..10
  visibility: MemoryVisibility;
  disclosure: string | null;
  origin: "self" | "observed";
  emotionalWeight: number | null;
  retention: MemoryRetention;
  policyVersion: number;
  updatedAt: string;
}
```

The layer registry remains policy authority. This row is the resolved per-memory projection. Exactly one
`taki-layer:<layerId>` tag must exist in `CanonicalMemoryUnit.tags`; repository mutation updates both in one
transaction. Tags from other namespaces are preserved. The projection is derived from the live registry without
reinterpreting it: `rollingDays` maps to `rolling-window.days`, `expiring` resolves to a concrete `expiresAt`, and
`archiveBelowImportance`/`afterDays` map unchanged to `importance-decay`. `unclassified` is an explicit reserved
fallback, not a fabricated registry row. A classified layer's `ownership` must match the target Bank scope.

The provider's ordinary read/write aggregate is explicit rather than flattened:

```ts
interface CanonicalMemoryRecord {
  unit: CanonicalMemoryUnit;
  policy: TakiMemoryPolicyProjection;
  provenance: MemoryProvenance;
}
```

`provenance` is read from the linked source when one exists, or uses `provider-derived` for a provider-created
observation with no retained source document in the replica.

### 4.8 Capabilities and error/result envelope

```ts
interface MemoryProviderCapabilities {
  providerId: MemoryProviderId;
  contractVersion: 1;
  retain: boolean;
  recall: boolean;
  reflect: boolean;
  edit: boolean;
  invalidate: boolean;
  restore: boolean;
  conditionalMutation: boolean;
  idempotentWrites: boolean;
  sparseRetrieval: boolean;
  vectorRetrieval: "unavailable" | "building" | "ready" | "degraded";
  derivedMemoryRead: boolean;
}

type MemoryErrorCode =
  | "MEMORY_INVALID_REQUEST"
  | "MEMORY_NOT_FOUND"
  | "MEMORY_REQUEST_ID_CONFLICT"
  | "MEMORY_REVISION_MISMATCH"
  | "MEMORY_CAPABILITY_UNSUPPORTED"
  | "MEMORY_AUTHORITY_MISMATCH"
  | "MEMORY_OPERATION_CANCELLED"
  | "MEMORY_PROVIDER_UNAVAILABLE"
  | "MEMORY_INTEGRITY_ERROR"
  | "MEMORY_INTERNAL_ERROR";

interface MemoryError {
  code: MemoryErrorCode;
  category: "validation" | "not-found" | "conflict" | "capability" | "authority" | "availability" | "integrity" | "internal";
  message: string; // bounded, sanitized, no memory/query/secret body
  retryable: boolean;
  nextAction: "fix-request" | "refresh-memory" | "retry" | "check-provider" | "none";
  currentRevision?: number;
}

type MemoryResult<T> =
  | {
      ok: true;
      requestId: string;
      providerId: string;
      authorityEpochId: string;
      capabilities: MemoryProviderCapabilities;
      data: T;
    }
  | {
      ok: false;
      requestId: string;
      providerId: string;
      authorityEpochId: string | null;
      capabilities: MemoryProviderCapabilities | null;
      error: MemoryError;
    };
```

Local's initial capability snapshot is retain/recall/edit/invalidate/restore/conditionalMutation/idempotentWrites/
sparseRetrieval = true; reflect/derivedMemoryRead = false; vectorRetrieval = unavailable unless an injected later
implementation reports otherwise.

### 4.9 Operation contracts

Provider requests target one Bank. Taki's Global/Character/both routing remains an outer policy concern.

```ts
interface RetainRequest {
  bankId: string;
  content: string;
  context: string | null;
  timestamp: string | null; // strict Zod accepts ISO datetime, literal "unset", or null
  tags: string[];
  entities: string[];
  metadata: Record<string, JsonValue>;
  observationScopes: "shared" | string[][] | null;
  documentId: string | null;
  strategy: string | null;
  updateMode: "replace" | "append";
  provenance: MemoryProvenance;
  policy: Omit<TakiMemoryPolicyProjection, "authorityEpochId" | "bankId" | "memoryId" | "updatedAt">;
}

interface RecallRequest {
  bankId: string;
  query: string;
  queryTimestamp: string | null;
  budget: "low" | "mid" | "high";
  limit: number;
  maxTokens: number;
  factTypes: Array<"world" | "experience" | "observation">;
  layerIds: string[];
  includeInvalidated: false;
}

interface ReflectRequest {
  bankId: string;
  query: string;
  budget: "low" | "mid" | "high";
  maxTokens: number;
}

type MutationRequest =
  | { kind: "edit"; bankId: string; memoryId: string; expectedRevision: number; patch: EditableMemoryPatch }
  | { kind: "invalidate"; bankId: string; memoryId: string; expectedRevision: number; reason: string | null }
  | { kind: "restore"; bankId: string; memoryId: string; expectedRevision: number };
```

The operation result families are equally strict and provider-neutral:

```ts
interface RetainResult {
  status: "completed";
  documentId: MemoryDocumentId;
  sourceRevision: MemoryRevision;
  memories: Array<{ memoryId: MemoryUnitId; revision: MemoryRevision }>;
}

interface RecallScore {
  source: "sparse" | "vector" | "hybrid" | "provider";
  value: number;
  higherIsBetter: boolean;
}

interface RecallHit {
  record: CanonicalMemoryRecord;
  scores: RecallScore[];
  confirmed: boolean;
}

interface RecallResult {
  hits: RecallHit[];
  returned: number;
  truncated: boolean;
  vectorState: "unavailable" | "building" | "ready" | "degraded";
  partial: boolean;
  branchFailures: Array<{
    scope: "global" | "character";
    code: MemoryErrorCode;
    retryable: boolean;
    nextAction: MemoryError["nextAction"];
  }>;
}

interface ReflectEvidence {
  memoryIds: MemoryUnitId[];
  mentalModelIds: string[];
  directiveIds: string[];
}

interface ReflectResult {
  text: string;
  structuredContent: JsonValue | null;
  evidence: ReflectEvidence;
  usage: { inputTokens: number | null; outputTokens: number | null };
  trace: Record<string, JsonValue> | null;
}

interface MutationResult {
  outcome: "applied" | "unchanged";
  record: CanonicalMemoryRecord;
}

type EditResult = MutationResult;
type InvalidateResult = MutationResult;
type RestoreResult = MutationResult;
```

Every string, collection, finite score, trace, and token/count field has a concrete bound in Zod.
`RetainResult.memories` supports Local's one-unit result and Hindsight's one-to-many extraction without duplicated ID/
revision maps. Recall scores preserve provider stages and score direction without making a particular ranking
algorithm authoritative. Reflect preserves Hindsight's
public text, structured output, evidence, usage, and trace families, while Local reports the operation unsupported.
Mutation not-found and stale-revision outcomes remain typed errors; `unchanged` is the successful same-lifecycle-state
case and does not advance the revision. A one-Bank provider recall returns `partial=false` and no branch failures. The
tool's `both` adapter may return bounded hits from one successful Bank with `partial=true` and a sanitized branch
failure; if neither Bank succeeds it returns the ordinary error envelope.

Shared exports named request/result schemas for each of the six tool families even where edit/invalidate/restore reuse
the same mutation data shape. This prevents callers from weakening the discriminant or treating one operation's input
as another's merely because their success payloads match.

`EditableMemoryPatch` allows text, context, `occurredStart`, `occurredEnd`, fact type (`world|experience` only),
entities, and Taki layer reclassification. It rejects empty patches. Event/mention/source timestamps are not silently
made editable because the accepted Hindsight curation contract does not expose them. Agent-facing tools expose
Hindsight-aligned names:

- `retain`
- `recall`
- `reflect` only when supported
- `update_memory`
- `invalidate_memory`
- `restore_memory`

The runtime creates `requestId`; it is never a model input. Recall results contain stable `memoryId`, current revision,
logical fields, Taki policy, bounded scores, and confirmation `confirmed` (always true in Local Batch 1). Observed
content is fenced by the existing untrusted fence before it is returned to a model tool.

Provider requests are not model schemas. The isolated tool adapters bind Bank/epoch/provider identity through a
trusted Core context and expose small strict-ready inputs: `retain` takes content, layer, and explicit nullable context;
`recall` takes query, scope, limit, and token cap; `reflect` takes query, one scope, budget, and token cap;
`update_memory` takes scope, memory ID, expected revision, and a bounded patch; lifecycle tools take scope, memory ID,
expected revision, and invalidate reason where applicable. `scope` is `global | character | both` for recall and
`global | character` for single-target operations. A trusted `MemoryToolBankRouter`, bound to the active Character,
resolves those enums to Bank IDs; no opaque Bank ID is invented by the model. Retain derives one target from the
classified layer's registry ownership; Write Gate `both` routing remains a later runtime concern. A recall against
both Banks invokes the same authority provider twice and is not provider failover. All fields are
required on the wire, using explicit `null` where omission would otherwise be ambiguous. Tool descriptions, per-field
descriptions, never-throw results, retry posture, and collision behavior follow `backend/tool-design.md`. The
user-approved Hindsight names are a documented exception to the local family-prefix naming preference, not permission
to advertise a second tool suite.

Retain carries Hindsight's public entities and observation scopes rather than hiding them in metadata. Timestamp
semantics also match Hindsight explicitly: `null` resolves through the injected clock to "now", `unset`
means timeless `eventDate=null`, and an ISO timestamp is preserved as `eventDate`. Local sets `mentionedAt` from the
sanitized provenance capture time; it never treats `null` as timeless or passes the literal `unset` into an ISO column.

Recall always sets query time, budget, fact types, layer-tag filtering, token/result caps, and required include behavior
explicitly at the provider adapter; it never depends on Hindsight transport defaults. Include behavior is adapter-owned
because the canonical result always requires entities, source lineage, and stable record fields.

The `retain.layer` schema is built from the live foreground-writable layer registry, using the same runtime-enum pattern
as other vocabulary-bound Core tools. It never offers `unclassified` or a machine-only layer to the model. The
provider schema still accepts the reserved `unclassified` projection for provider-derived/imported facts.

`createCanonicalMemoryTools` is asynchronous: it awaits one coordinator capability snapshot, builds only supported
definitions, and returns a `Promise<ToolSet>`. Execution still rechecks authority and capability through the
coordinator, so a stale definition cannot bypass policy. Batch 1 keeps this factory isolated; the later runtime
activation must await it before final collision-safe tool assembly instead of adding a synchronous capability cache.

## 5. SQLite Ownership and Schema

Migration target: the next available numbered Core migration (currently `017`) registered explicitly in
`packages/core/src/db/migrations/index-list.ts`. Names are intentionally distinct from legacy `memory_entries` and
`memory_fts`.

The DDL below is normative in shape. Implementation may adjust index names or SQL formatting, but not ownership,
keys, lifecycle constraints, or the activation boundary.

```sql
CREATE TABLE canonical_memory_authority_epochs (
  epoch_id             TEXT PRIMARY KEY,
  provider_id          TEXT NOT NULL,
  provider_lineage_id  TEXT NOT NULL,
  status               TEXT NOT NULL CHECK (status IN ('active', 'closed')),
  predecessor_epoch_id TEXT REFERENCES canonical_memory_authority_epochs(epoch_id),
  started_at           TEXT NOT NULL,
  ended_at             TEXT,
  reason               TEXT NOT NULL CHECK (reason IN ('initial-local', 'planned-switch', 'emergency-takeover')),
  CHECK ((status = 'active' AND ended_at IS NULL) OR (status = 'closed' AND ended_at IS NOT NULL))
) STRICT;
CREATE UNIQUE INDEX idx_canonical_memory_one_active_epoch
  ON canonical_memory_authority_epochs(status) WHERE status = 'active';

CREATE TABLE canonical_memory_authority_state (
  singleton       INTEGER PRIMARY KEY CHECK (singleton = 1),
  active_epoch_id TEXT NOT NULL REFERENCES canonical_memory_authority_epochs(epoch_id),
  updated_at      TEXT NOT NULL
) STRICT;

CREATE TABLE canonical_memory_banks (
  authority_epoch_id TEXT NOT NULL REFERENCES canonical_memory_authority_epochs(epoch_id),
  bank_id            TEXT NOT NULL,
  scope_kind         TEXT NOT NULL CHECK (scope_kind IN ('global', 'character')),
  character_id       TEXT,
  name               TEXT NOT NULL,
  disposition_json   TEXT NOT NULL CHECK (json_valid(disposition_json)),
  mission            TEXT NOT NULL,
  config_json        TEXT NOT NULL CHECK (json_valid(config_json)),
  revision           INTEGER NOT NULL CHECK (revision >= 1),
  created_at         TEXT NOT NULL,
  updated_at         TEXT NOT NULL,
  PRIMARY KEY (authority_epoch_id, bank_id),
  CHECK ((scope_kind = 'global' AND character_id IS NULL) OR
         (scope_kind = 'character' AND character_id IS NOT NULL AND length(character_id) > 0))
) STRICT;
CREATE UNIQUE INDEX idx_canonical_memory_bank_scope
  ON canonical_memory_banks(authority_epoch_id, scope_kind, ifnull(character_id, ''));

CREATE TABLE canonical_memory_sources (
  authority_epoch_id     TEXT NOT NULL,
  bank_id                TEXT NOT NULL,
  document_id            TEXT NOT NULL,
  content_hash           TEXT,
  retained_text          TEXT,
  context                TEXT,
  tags_json              TEXT NOT NULL CHECK (json_valid(tags_json)),
  metadata_json          TEXT NOT NULL CHECK (json_valid(metadata_json)),
  observation_scopes_json TEXT CHECK (observation_scopes_json IS NULL OR json_valid(observation_scopes_json)),
  provenance_json        TEXT NOT NULL CHECK (json_valid(provenance_json)),
  revision               INTEGER NOT NULL CHECK (revision >= 1),
  created_at             TEXT NOT NULL,
  updated_at             TEXT NOT NULL,
  PRIMARY KEY (authority_epoch_id, bank_id, document_id),
  FOREIGN KEY (authority_epoch_id, bank_id)
    REFERENCES canonical_memory_banks(authority_epoch_id, bank_id)
) STRICT;

CREATE TABLE canonical_memory_units (
  authority_epoch_id        TEXT NOT NULL,
  bank_id                   TEXT NOT NULL,
  memory_id                 TEXT NOT NULL,
  document_id               TEXT,
  chunk_id                  TEXT,
  text                      TEXT NOT NULL,
  context                   TEXT,
  fact_type                 TEXT NOT NULL CHECK (fact_type IN ('world', 'experience', 'observation')),
  state                     TEXT NOT NULL CHECK (state IN ('valid', 'invalidated')),
  revision                  INTEGER NOT NULL CHECK (revision >= 1),
  tags_json                 TEXT NOT NULL CHECK (json_valid(tags_json)),
  metadata_json             TEXT NOT NULL CHECK (json_valid(metadata_json)),
  entities_json             TEXT NOT NULL CHECK (json_valid(entities_json)),
  observation_scopes_json   TEXT CHECK (observation_scopes_json IS NULL OR json_valid(observation_scopes_json)),
  event_date                TEXT,
  occurred_start            TEXT,
  occurred_end              TEXT,
  mentioned_at              TEXT,
  created_at                TEXT NOT NULL,
  updated_at                TEXT NOT NULL,
  edited_at                 TEXT,
  consolidated_at           TEXT,
  consolidation_failed_at   TEXT,
  invalidation_reason       TEXT,
  invalidated_at            TEXT,
  proof_count               INTEGER NOT NULL CHECK (proof_count >= 1),
  PRIMARY KEY (authority_epoch_id, bank_id, memory_id),
  FOREIGN KEY (authority_epoch_id, bank_id)
    REFERENCES canonical_memory_banks(authority_epoch_id, bank_id),
  FOREIGN KEY (authority_epoch_id, bank_id, document_id)
    REFERENCES canonical_memory_sources(authority_epoch_id, bank_id, document_id),
  CHECK ((state = 'valid' AND invalidated_at IS NULL AND invalidation_reason IS NULL) OR
         (state = 'invalidated' AND invalidated_at IS NOT NULL))
) STRICT;
CREATE INDEX idx_canonical_memory_units_recall
  ON canonical_memory_units(authority_epoch_id, bank_id, state, updated_at DESC);
CREATE INDEX idx_canonical_memory_units_document
  ON canonical_memory_units(authority_epoch_id, bank_id, document_id);

CREATE TABLE canonical_memory_unit_sources (
  authority_epoch_id TEXT NOT NULL,
  bank_id            TEXT NOT NULL,
  memory_id          TEXT NOT NULL,
  source_memory_id   TEXT NOT NULL,
  PRIMARY KEY (authority_epoch_id, bank_id, memory_id, source_memory_id),
  FOREIGN KEY (authority_epoch_id, bank_id, memory_id)
    REFERENCES canonical_memory_units(authority_epoch_id, bank_id, memory_id),
  FOREIGN KEY (authority_epoch_id, bank_id, source_memory_id)
    REFERENCES canonical_memory_units(authority_epoch_id, bank_id, memory_id),
  CHECK (memory_id <> source_memory_id)
) STRICT;
CREATE INDEX idx_canonical_memory_unit_sources_reverse
  ON canonical_memory_unit_sources(authority_epoch_id, bank_id, source_memory_id, memory_id);

CREATE TABLE canonical_memory_derived (
  authority_epoch_id TEXT NOT NULL,
  bank_id            TEXT NOT NULL,
  object_id          TEXT NOT NULL,

CREATE TABLE canonical_memory_policy (
  authority_epoch_id TEXT NOT NULL,
  bank_id            TEXT NOT NULL,

  emotional_weight   REAL,
  retention_json     TEXT NOT NULL CHECK (json_valid(retention_json)),

  updated_at         TEXT NOT NULL,
  PRIMARY KEY (authority_epoch_id, bank_id, memory_id),
  FOREIGN KEY (authority_epoch_id, bank_id, memory_id)

CREATE INDEX idx_canonical_memory_policy_layer
  ON canonical_memory_policy(authority_epoch_id, bank_id, layer_id, visibility);

CREATE TABLE canonical_memory_operation_receipts (

  request_id         TEXT NOT NULL,
  operation          TEXT NOT NULL CHECK (operation IN ('retain', 'edit', 'invalidate', 'restore')),
  request_hash       TEXT NOT NULL,

  created_at         TEXT NOT NULL,

  block_row_id  INTEGER PRIMARY KEY,
  block_id      TEXT NOT NULL,
  scope_kind   TEXT NOT NULL CHECK (scope_kind IN ('global', 'character')),
  character_id TEXT,
  content      TEXT NOT NULL,
  revision     INTEGER NOT NULL CHECK (revision >= 1),
  updated_at   TEXT NOT NULL,
  CHECK ((scope_kind = 'global' AND character_id IS NULL) OR
         (scope_kind = 'character' AND character_id IS NOT NULL AND length(character_id) > 0))
) STRICT;
CREATE UNIQUE INDEX idx_taki_memory_blocks_scope
  ON taki_memory_blocks(block_id, scope_kind, ifnull(character_id, ''));

CREATE VIRTUAL TABLE canonical_memory_fts USING fts5(
  authority_epoch_id UNINDEXED,
  bank_id UNINDEXED,
  memory_id UNINDEXED,
  text,
  context,
  search_terms,
  tokenize='unicode61'
);
```

`taki_memory_blocks` deliberately has no authority epoch foreign key: it is current Core-owned companion policy, not
a provider logical branch. The block registry validates whether a block is global/per-character and who may write it.
`block_row_id` is an internal SQLite key only. The logical identity is the expression-backed unique scope index;
keeping nullable `character_id` out of a `STRICT` composite primary key is required because such primary-key columns
become implicitly `NOT NULL`, which would make every global Block impossible to insert.

The implementation must parse every JSON column through the shared Zod schema at the repository boundary. `json_valid`
is corruption defense, not semantic validation. `sourceMemoryIds` is normalized through
`canonical_memory_unit_sources`, so every lineage edge is constrained to the same epoch and Bank. Derived-row parsing
also proves that `kind`, `object_id`, `bank_id`, and `object_revision` agree with the payload/envelope rather than
trusting duplicate JSON blindly.

## 6. Core Interfaces

### 6.1 Provider and call context

```ts
interface MemoryProviderCallContext {
  requestId: string;
  authorityEpochId: string;
  actor: "foreground-agent" | "background-policy" | "operator" | "migration";
  signal?: AbortSignal;
}

interface MemoryProvider {
  readonly providerId: string;
  readonly providerLineageId: string;
  capabilities(): Promise<MemoryProviderCapabilities>;
  retain(ctx: MemoryProviderCallContext, request: RetainRequest): Promise<MemoryResult<RetainResult>>;
  recall(ctx: MemoryProviderCallContext, request: RecallRequest): Promise<MemoryResult<RecallResult>>;
  reflect(ctx: MemoryProviderCallContext, request: ReflectRequest): Promise<MemoryResult<ReflectResult>>;
  mutate(ctx: MemoryProviderCallContext, request: MutationRequest): Promise<MemoryResult<MutationResult>>;
}
```

All methods are async by contract. Cancellation is internal call context, never model input. Local checks an already
aborted signal before starting but does not interrupt a synchronous transaction midway; a later network provider passes
the same signal to transport calls. The Local implementation performs no `await` inside `Database.transaction`; it
computes IDs/hashes before the transaction, executes synchronous repository work, commits, and then resolves the
Promise.

### 6.2 Coordinator

```ts
interface MemoryCoordinatorCallOptions {
  requestId?: string;
  actor?: MemoryProviderCallContext["actor"];
  expectedAuthorityEpochId?: string;
  signal?: AbortSignal;
}

interface MemoryCoordinator {
  capabilities(): Promise<MemoryProviderCapabilities>;
  retain(request: RetainRequest, call?: MemoryCoordinatorCallOptions): Promise<MemoryResult<RetainResult>>;
  recall(request: RecallRequest, call?: MemoryCoordinatorCallOptions): Promise<MemoryResult<RecallResult>>;
  reflect(request: ReflectRequest, call?: MemoryCoordinatorCallOptions): Promise<MemoryResult<ReflectResult>>;
  mutate(request: MutationRequest, call?: MemoryCoordinatorCallOptions): Promise<MemoryResult<MutationResult>>;
}
```

`MemoryCoordinatorCallOptions` permits only an injected request ID for deterministic tests/replay, actor, expected
authority epoch, and `AbortSignal`. It is an internal Core type, not a Shared/model schema. The coordinator always
loads the persisted active epoch; an optional expected epoch is a stale-work precondition, never an authority selector.

Coordinator algorithm:

1. Generate a UUID request ID if absent.
2. Load the persisted active epoch.
3. Resolve exactly the provider whose ID and provider lineage match that epoch.
4. Read its capability snapshot and reject unsupported operations.
5. Pass the active epoch and request ID to the provider.
6. Validate the returned envelope through Shared Zod.
7. Convert unexpected exceptions to `MEMORY_INTERNAL_ERROR` without memory/query/secret text.

There is no fallback branch. A missing provider registration is `MEMORY_PROVIDER_UNAVAILABLE`; an epoch/provider ID or
provider-lineage mismatch is `MEMORY_AUTHORITY_MISMATCH`.

### 6.3 Local repositories

Recommended split, matching existing Core patterns:

- `canonical-memory-authority-repo.ts`: initialize/read Local epoch; create/read Banks; no switch method in Batch 1.
- `canonical-memory-repo.ts` (split into named record/receipt modules if needed for the line cap): source/unit/derived/
  lineage/policy/receipt transactions and typed row parsing.
- `canonical-memory-sparse-repo.ts`: FTS upsert/delete/search/rebuild and BM25 result projection.
- `structured-memory-block-repo.ts`: block registry checks, revisioned whole-document read/write, no FTS dependency.

Only the Local Provider composes these repositories into write transactions. Other code does not write tables
directly.

### 6.4 Optional vector seam

```ts
interface MemoryVectorProjection {
  status(): Promise<"building" | "ready" | "degraded">;
  scheduleUpsert(record: CanonicalMemoryRecord): void;
  scheduleDelete(ref: { authorityEpochId: string; bankId: string; memoryId: string }): void;
  search(request: RecallRequest): Promise<VectorRecallCandidate[]>;
  rebuild(records: AsyncIterable<CanonicalMemoryRecord>): Promise<void>;
}
```

The projection owns its queue, retry, and lag state. Local canonical commits never await it. Batch 1 ships only the
interface and an absent/disabled path, so capabilities report `unavailable` and recall uses sparse results alone. A
later implementation may combine sparse and vector candidates by weighted union behind the same provider result.

## 7. Data Flows

### 7.1 Initialize Local authority

1. Open/migrate SQLite. The migration creates empty canonical tables only.
2. An explicit canonical factory/test calls `initializeLocalAuthority`.
3. In one transaction, if no authority state exists, insert a UUID Local epoch, a UUID Local provider lineage, and the
   singleton pointer. If one exists, validate that it points to one active Local epoch with a valid lineage and return
   both identities unchanged.
4. A malformed, missing-target, non-Local, or multiple-active state is an integrity error. Batch 1 never repairs or
   switches it automatically.

Production does not call this factory until Batch 2 activation.

### 7.2 Local retain

1. Coordinator resolves the active Local epoch and capability.
2. Validate request, layer registry projection, provenance, Bank, bounds, and classified-layer ownership against the
   Bank scope.
3. Derive request fingerprint; choose document ID (`request.documentId` or a request-ID-based opaque ID), memory ID,
   timestamps, content hash, and exactly one `taki-layer:*` tag before the transaction.
4. In one synchronous transaction:
   - if `(epoch, requestId)` receipt exists, return it when hash/operation match; otherwise return request-ID conflict;
   - re-read active epoch and Bank;
   - for a new document, insert the source, one `experience` unit, policy projection, and FTS row;
   - for `updateMode=replace` on an existing Local document, increment the source revision, invalidate its prior valid
     Local unit(s), remove their FTS rows, and insert one replacement unit/policy/FTS row while preserving history;
   - insert the minimal success receipt (IDs/revisions only).
5. Commit, optionally schedule a vector upsert, and return `completed`.

`updateMode=append` and a non-null provider extraction `strategy` are schema-compatible but Local Batch 1 returns
capability unsupported for either. It must never silently behave as replace or pretend to honor a strategy. Local
maintains exactly one valid unit for a document after each completed retain; the schema still permits Hindsight's
one-to-many document mapping. A replacement uses a fresh memory ID and reversibly invalidates the prior Local unit
rather than permanently deleting it.

### 7.3 Local mutation

1. Validate non-empty edit or lifecycle operation; compute request hash.
2. In one transaction, check idempotent receipt and active epoch.
3. Load the target by `(epoch, bank, memoryId)` and compare `expectedRevision`.
4. On mismatch, make no writes and return `MEMORY_REVISION_MISMATCH` with current revision.
5. Apply edit and increment revision, including a same-value explicit edit. Invalidate/restore increment only on an
   actual lifecycle transition; requesting the current state writes an `unchanged` receipt and keeps the revision.
6. If layer changes, update policy and replace only the controlled `taki-layer:*` tag in the unit atomically.
7. Upsert or remove FTS based on resulting lifecycle; write receipt; commit.
8. Schedule vector update/delete only after commit.

An exact replay returns its original receipt even though the current revision has advanced. Reusing a request ID for a
different fingerprint returns conflict.

### 7.4 Sparse recall

1. Validate active epoch, Bank, bounds, fact types, and layer filters.
2. Tokenize the query with the same `SearchTokenizer` used for projection.
3. Query `canonical_memory_fts`, join canonical unit and policy rows, and filter active epoch/Bank/valid lifecycle.
4. Rank by BM25, then deterministic importance/update/ID tie breaks.
5. Optionally ask an injected ready vector projection and combine by a provider-internal weighted union; vector
   absence/failure records bounded diagnostics and preserves sparse candidates.
6. Fit results to both `limit` and `maxTokens`; return current revision and policy with every hit.

Batch 1 tests sparse-only and injected vector failure. It does not freeze hybrid weights.

### 7.5 FTS rebuild

In one Core-owned transaction, delete all `canonical_memory_fts` rows, stream every valid canonical unit joined with
policy, tokenize text/context/disclosure, and reinsert. The result reports counts only. Blocks, sources, invalidated
units, mental models, and directives are excluded. A failed rebuild rolls back to the previous complete FTS state.

### 7.6 Structured Memory Blocks

1. Resolve the block definition from `V1_BLOCKS` and validate scope/writer.
2. Read or replace one whole structured row; writes increment revision.
3. Assembler-facing reads use registry order, headers, and budgets, not table order.
4. Missing rows render nothing. `user-card` remains user-written; background callers are rejected.
5. No provider, source/unit, receipt, FTS, or vector write occurs.

Batch 1 provides/test-drives the repository and renderer seam but does not replace the production Markdown block store
until Batch 2 activation.

## 8. Authority and Epoch Behavior in Batch 1

- One active epoch is mandatory for canonical operations.
- Only Local epoch initialization is implemented.
- Every operation carries and revalidates the expected epoch; provider ID and provider lineage must match that epoch.
- The coordinator never changes authority because of provider error.
- There is no Hindsight epoch, replica mode, branch merge, checkpoint, outbox, or takeover transition.
- Old/closed epoch data is structurally retained and excluded by active-epoch filters, preserving the later branch
  model without implementing switching now.

## 9. Error and Capability Semantics

| Condition | Code | Retryable | Next action |
| --- | --- | --- | --- |
| Zod/bounds/empty edit | `MEMORY_INVALID_REQUEST` | no | `fix-request` |
| Missing Bank/unit | `MEMORY_NOT_FOUND` | no | `refresh-memory` |
| Request ID reused for different work | `MEMORY_REQUEST_ID_CONFLICT` | no | `fix-request` |
| Stale expected revision | `MEMORY_REVISION_MISMATCH` | no | `refresh-memory` |
| Reflect/vector/source append/provider strategy unsupported | `MEMORY_CAPABILITY_UNSUPPORTED` | no | `none` |
| Persisted epoch/provider disagreement | `MEMORY_AUTHORITY_MISMATCH` | no | `check-provider` |
| Call signal already aborted / transport cancellation | `MEMORY_OPERATION_CANCELLED` | no | `none` |
| Configured provider absent/unreachable | `MEMORY_PROVIDER_UNAVAILABLE` | yes | `check-provider` |
| Broken DB invariants/Zod row parse | `MEMORY_INTEGRITY_ERROR` | no | `check-provider` |
| Unexpected sanitized failure | `MEMORY_INTERNAL_ERROR` | no | `check-provider` |

Capabilities describe usable behavior, not compiled code. An optional seam being present does not set a capability to
true until its implementation is healthy. Error code, category, retryability, and next action are validated as one
discriminated mapping; callers cannot construct contradictory combinations. Side-effecting retries reuse the same
request ID and never rely on a generic `retryable=true` internal error.

## 10. Concurrency, Transactions, and Idempotency

- Core remains the single SQLite writer. Use the existing synchronous `Database.transaction`; never await inside it.
- Source, unit, policy, FTS, and receipt publication is atomic.
- Mutation uses optimistic `expectedRevision`; timestamps never decide conflicts.
- Request receipts are durable and checked before revision validation, so exact retry returns the original committed
  result. Request ID reuse with a different canonical hash is a conflict.
- Request fingerprints use stable-key canonical JSON plus SHA-256. They exclude runtime-only diagnostics but include
  every semantic input.
- Document replacement and its prior-unit invalidation share the source/unit/policy/FTS/receipt transaction. Existing
  document identity never degrades into an untyped uniqueness error.
- The active epoch is read by the coordinator and rechecked inside write transactions. A future switch cannot commit a
  late write into the wrong epoch.
- FTS is updated in the canonical transaction for read-after-write. Rebuild remains the repair path.
- Vector work starts only after commit and never decides write success.

## 11. Compatibility, Activation, and Rollback

### Compatibility

- Migration 017 is additive. It does not alter `memory_entries`, `memory_fts`, `memory_auto_state`, Markdown files,
  current tools, prompts, assembler, or background chain.
- New canonical module names must not shadow the legacy `MemoryEngine`, `MemoryStore`, or `Retriever` exports.
- Existing production tests remain the proof that behavior did not switch.

### Activation boundary

- Batch 1 factories are imported only by isolated tests or non-production module consumers.
- `packages/core/src/main.ts` and `createMemorySubsystem` do not instantiate the coordinator/Local Provider.
- No legacy write calls canonical code and no canonical write calls legacy code.
- Batch 2 owns: normalization, migration ledger, block conversion, completeness verification, explicit canonical
  factory wiring, canonical tool/prompt activation, and removal/retirement timing for legacy writes.

### Rollback

- Before activation, rollback is to stop constructing the canonical factory. Legacy authority remains untouched.
- Empty/additive canonical tables may remain without behavioral effect.
- Once a migration number ships, do not rewrite it; fixes use a forward migration. During unshipped implementation,
  a broken migration may be corrected before acceptance.
- Batch 1 does not provide a reverse conversion from canonical data to Markdown. Export belongs to a later task.

## 12. Observability and Privacy

- Log provider ID, epoch ID, operation kind, request ID, Bank ID, outcome code, latency, and counts only.
- Never log retain text, source text, memory text, recall query, disclosure, tags, entities, provenance payload,
  metadata, tool arguments, or receipt JSON.
- Error messages are bounded fixed vocabulary plus opaque IDs where needed; raw SQLite/Zod/provider messages stay in a
  sanitized cause chain unavailable to model/UI payloads.
- Receipts store minimal IDs/revisions/status, not recall results or full source/unit bodies.
- Recall fences `origin="observed"` text before model exposure using the existing untrusted fence.
- Canonical source persistence accepts only content already sanitized by its caller. The future Write Gate/projector
  remains responsible for removing hidden prompts, injected recall, and secret-bearing tool payloads.
- No canonical content crosses the existing operator `memory.status` surface in Batch 1.

## 13. Alternatives and Tradeoffs

### Retrofit the existing Markdown engine

Rejected. The existing composition and IDs encode file authority, synchronous retrieval, and path-based repair. Adding
provider/epoch/revision behavior there would create dual semantics and make migration impossible to reason about.

### Mirror Hindsight PostgreSQL tables locally

Rejected. It would couple Taki to provider-private schema and operational queues. The accepted contract is a stable
logical projection only.

### Activate canonical Local immediately with no migration

Rejected. Existing workspaces would appear empty or require dual-write. Batch 2 must prove deterministic conversion
before activation.

### Keep Memory Blocks as Markdown while facts become structured

Rejected for the canonical subsystem. Runtime Markdown storage is retired, and Blocks are Taki policy state. A
structured block document preserves their special semantics without pretending they are Hindsight facts.

### Make provider APIs synchronous until Hindsight arrives

Rejected. It would force a breaking runtime/tool rewrite at network integration. Promise-based APIs cost almost
nothing around Local synchronous transactions.

### Require embeddings

Rejected. It would make Local unusable for users without an embedding model. Sparse retrieval is mandatory and
complete; vectors are a later optional projection.

### Generate Hindsight-like facts locally

Rejected. Local retain deliberately stores one already-selected memory unit. Recreating professional extraction,
dedupe, observations, and consolidation would repeat the self-built approximation this integration is replacing.
