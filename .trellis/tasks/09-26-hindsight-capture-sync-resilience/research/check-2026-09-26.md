## Review points

1. No lost turn: `chat-send.ts` -> `runs.admit` -> `run-snapshot-capture.ts` -> runtime `captureRun` -> `synchronizeHindsightCapture`.
   After F1 the only throws are caller cancellation, integrity / request-id conflict / a real authority change (each
   logged once at error with a closed code, then `-32603` with the closed code and one registry log), and the
   pre-existing all-synced-without-evidence `HINDSIGHT_APPLICATION_ADMISSION_UNAVAILABLE`.
2. Conflict retry: at most 1 + `BIND_CONFLICT_RETRIES` (3) consecutive conflicting binds per run; each retry is a new
   intent digest after a fresh incremental pull, and the refused receipt is durable for its own request id, so no
   duplicate native effect (tests: 1 refused + 1 completed; 4 refused then exactly 1 completed later).
3. Budget: `admissionBudgetMs()` resolves `TAKI_CHAT_ACK_TIMEOUT_MS` per capture (live test passes); timer cleared in
   `finally`, abort listener removed, `syncBanks` never rejects, detached work is tracked in the Bank service `active`
   set that `stop()` aborts and `settle()` drains; a Bank started after stop fails at its first `request()` before any
   SQLite access.
4. W2 fence: `fenceHindsightWriters` still wraps `captureRun` only to fence the Run's write tools; the admission sync and
   its binding commits are not fenced, so capture stays open during a backup capture. Fence tests pass.
5. R4 logging: `{ method, code }` only; code is a CONSTANT_CASE message or the error class; params/bodies/messages
   never logged; `JSONRPCErrorException` not logged. Only `main.ts` creates the registry and passes the logger.
6. Headers/index/sizes: headers and `index.md` match; sizes fine (capture-sync 103, sync-runner 230, subsystem 169,
   method-registry 132; functions <= 50, params <= 3). New tests are behavioral. The curator fixture change keeps
   curator intent (stale CAS is still refused, now as native does).
