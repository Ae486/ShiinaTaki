# core/memory/transitions/

W3 prepares complete immutable candidates and deltas. W4 owns authority/custody/queue COMMIT and runtime publication;
W5 owns orchestration. These modules never temporarily select a candidate or manufacture first-activation receipts.

- transition-native-loader.ts — authenticated complete native/application/maintenance/auxiliary page and body loading.
- transition-native-evidence.ts — proof identity, page/hash/count and full original body/history closure verification.
- transition-local-encoding.ts — lossless internal Local JSON hashes; frozen native wire hashes remain separate.
- transition-local-projection.ts — stable physical/logical object identity, canonical projection and proved policy initialization.
- transition-local-timestamps.ts — Local edit times preserved only by exact baseline/final field and native-reuse evidence.
- transition-historical-references.ts — genuine native tombstone/source-reference lineage without fake live units.
- transition-source-aliases.ts — independent append-fragment aliases and ordered exact historical Source references.
- transition-pending-sources.ts — current awaiting Source evidence for factual W4 custody disposition, never confirmed records.
- transition-local-candidate.ts — all-Bank isolated Local candidate, stable scope IDs, Blocks/history and common baseline.
- transition-evidence-context.ts — synchronous boundary-local complete native verification; same-owner stored-byte checks, immutable JSON and isolated body views without cross-stage caching.
- transition-delta-rows.ts — complete native reuse/upsert/delete descriptors with actual Local retirement evidence.
- transition-delta-application.ts — complete application inventory and policy/Block changes preserving old artifacts.
- transition-delta-sources.ts — alias-only Source changes and exact existing/this-delta ordered Memory selectors.
- transition-unused-delta.ts — new Local scope with actual native unused-scope proof and complete ordered SourceSets resolved to same-delta Source outputs; no reset/full-copy fallback.
- transition-source-upload.ts — exact original byte/ID upload recovery with durable executor attempts and current Core guards.
- transition-delta-execution.ts — historical result lookup before effects, exact immutable result storage and replay.
- transition-final-mapping.ts — post-maintenance mapping joins, final Hindsight candidate and independent COMMIT-time read-back.
- transition-queued-provider.ts — original-call admission into bounded typed custody, distinct queue ACK/refusals and immutable provenance.
- transition-queue-mapping.ts — exact target scope, logical identity and original/current CAS revision before dispatch.
- transition-intent-executor.ts — ordered fresh target requests, actual receipt/refusal recovery and unknown ownership across restart/shutdown.
- transition-runtime.ts — production composition of drain, proof, COMMIT, native readiness/release, source repair and queued execution.
- transition-current-identity.ts — current reviewed connection, independent Character coverage and healthy common-baseline identity.
- transition-native-session.ts — all-Bank original acquire/claim/verify/decision dispatch and authenticated historical reconciliation.
- transition-native-decision.ts — immutable finalization decisions and proof-bound continuation of an original refused abort.
- transition-healthy-candidate.ts — complete return candidate or current-Local delta followed by every Bank's final native proof; reuses immutable verified evidence only under the same original request and sealed proof after executor changes.
- transition-unused-inventory.ts — complete unused-Bank reads with one expiry-qualified renewal per invocation, append-only snapshot request chains and current source/fence/namespace guards.
- transition-healthy-execution.ts — operation-owned drain, proof, atomic publication and finalization; preserves interrupted055 return or abort intent and logs only closed failure codes/stages.
- transition-healthy-service.ts — current previews, synchronous admission, explicit recovery and joined shutdown over the existing owner.
- transition-healthy-status.ts — factual per-Bank/queue/runtime/release observations independent of the selected provider.

Adjacent tests cover complete closure, SQLite staging/reopen/CAS, ordinary Local mutations/retention, mixed scope
identity, exact delta recovery, Source copies/history and timestamp provenance. Task-owned HTTP/PG and real-data
structural fixtures provide the separately recorded producer and historical-corpus evidence. Complete-driver snapshot
recovery covers physical reconstruction, earlier prepared deltas, application page expiry, lost renewed replies,
bounded repeated expiry, typed/non-typed refusal distinctions and strict historical proof/ownership guards.
The Source upload journey preserves its original 100,000-character multibyte body and full roundtrip assertions,
requires exactly two upload parts, and uses a measured 60-second per-test budget rather than a global timeout change.
