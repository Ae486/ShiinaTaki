## W7 control HTTP failure and causal validation

The retained loop is the actual W7 browser scenario. Its first new failure is Python line 45, reading the Native
call-count baseline after successful RETURN, reconnect/original-operation checks and REENTRY, before emergency.
The complete captured stdout/stderr contains no preceding Node/Vite exception. That first observation alone did
not establish reproducibility or cause. No browser assertion or deadline was weakened, and no blind retry ran.

Following the `diagnose` skill, three ranked falsifiable hypotheses were reported before another W7 run:

1. The control request reuses a socket during an idle-close race. Installed Playwright `server/fetch.js` selects
   the global HTTP agent, `utils/happyEyeballs.js:75` enables keep-alive, and retries default to zero. Prediction:
   the failed request never reaches its handler; an existing socket times out/closes while the server stays alive.
2. The owned Vite HTTP server or fixture closes unexpectedly. Prediction: server close/error or teardown precedes
   the Python failure, and subsequent new connections cannot reach the server.
3. A control response is aborted inside the route. Prediction: the handler receives the request but no response
   finish is observed, while HTTP/WS listeners remain live. This ranks lower because current control state and
   Native counters are plain booleans/numbers with no normal serialization failure path.

failure (exit 1, 32.484 seconds; 2,058 inputs, zero changed inputs, temporary root removed). Its payload-free
