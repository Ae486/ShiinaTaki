## Decisions that can be retained

1. **One Agent engine with separate work ports is a sound fit.** `chat-agent.ts:301-367` already owns Replay selection, tools/disclosure, ToolLoopAgent and the provider stream. Its non-primary recording early return at `:270-272` is a real missing private-history seam. Reusing that loop with a work-context source and private sink is smaller than a second executor. The sink must also cover the new internal parent-continuation Runs.
2. **The four record families have distinct necessary jobs.** Stable child continuity, accepted addressed inputs, private Run messages and execution/result/outbox linkage cannot be collapsed into the Character Timeline without losing the agreed separation. `active_run_id` may be a transactional coordination pointer, not an independent Run state. No additional session framework or event-sourced scheduler is needed.
3. **The target SDK supports the proposed safe-step steering mechanism.** Published `ai@7.0.148/src/generate-text/stream-text.ts:2433-2450,2499-2503` passes the current messages into `prepareStep`; `:1773-1777` retains that step's selected messages plus responses for the next step. An injected message does not inherently disappear on the following step. The WorkContext callback must compose with disclosure and distinguish newly included input from already-carried messages. No custom model loop is justified.
4. **Independent child lanes/controllers and a durable user-stop latch match G4.** Current `turn-registry.ts:28-31` would overwrite a Character's controller. Extending this owner with exact work scope is the right correction. Primary stop must remain separate from user child stop, parent interruption, temporary business-owner yield and actual process shutdown.
5. **Optional material-level metadata and native messages are sufficient as the common representation.** Do not require identical source fields, a semantic classifier, per-sentence provenance or all-seen-material attribution. The same-day `{inputId, key}` correction resolves collisions between equal keys in different addressed inputs. `entry_kind` likewise resolves input/output index collisions in private rows; these are not outstanding findings.
6. **The source sidecar repairs an evidenced loss.** `co-watching/runtime.ts:126-129` drops known media/moment detail, and `run-delivery-repo.ts:119-139` appends speech without that description. Exact immutable candidate-to-delivery-to-Timeline metadata is preferable to reconstructing historical speech from mutable task files. Metadata belongs in candidate equality/digests and the final Timeline transaction.
7. **Memory remains a parallel consumer of eligible originals.** `canonical-ingestion-source.ts:47-73,107-115` verifies primary witnesses and excludes tool material; `:81-98` separates prompt framing from unchanged retained wording/offsets. Preserve the conditional legacy digest strategy, explicit SQL readers, one gate and existing provider authority. Do not admit child transcripts, non-primary deliveries or compaction summaries to compensate for missing attribution.
8. **Additive migration and rollback are appropriate.** Keep new records and nullable columns, immutable historical speech and unknown legacy attribution. `sqlite.ts:73-93` already supports true COMMIT failure rollback and nested savepoints. A rollback binary that ignores newly necessary source meaning is not a successful semantic rollback; the proposed compatibility-reader/forward-fix approach is sound.

## Required design corrections

### R1. Scope supersession to work, not to the reusable child's newest input

**Scenario.** Work A completes with `request_parent`, but foreground activity defers its parent continuation. The parent reuses the same child for independent work B with `record_only`. Section 11 currently says a newer child input closes A's continuation/publication eligibility; section 6 similarly supersedes a final result whenever an unselected pending input exists. That suppresses A's captured completion intent even though B is explicitly a separate `work` record. The new `input_kind` distinction in section 4 does not resolve this: no durable target-work field tells a message after queued B whether it belongs to active A or B.

**Why this is a blocker.** G1 retains per-work completion choice; G2 explicitly permits reuse without reopening terminal Runs; G3 lets the parent choose what to address. Child continuity is not itself a source revision. Existing publication validity is scoped to an exact accepted source/candidate revision (`prepared-publication-source.ts:89-112`), not all later activity on a worker. Blanket child-sequence invalidation would introduce a new policy that silently drops needed inference.

**Bounded correction.** Persist a stable work identity using the already-minted triggering work input ID; no fifth record family is necessary. Each steering/continuation input records the exact `workInputId` it addresses, resolved at acceptance against the stated active/expected target. A new `work` input owns a new identity and waits without mutating A. Retain child-global sequence for display/order, but use work identity plus that work's input watermark and optional source revision for result eligibility. A same-work late correction can supersede A's output and schedule its corrected execution; independent B cannot. A new work request may explicitly replace older work only through a represented, validated replacement action, not by mere reuse.

**Verification.** Test A/request-parent + deferred completion + B/record-only; A still admits exactly one parent continuation. Test an actual correction of A, which withholds its stale report. Test A active, B queued, then an addressed message for A; restart must preserve which work owns it. Do not silently batch two `work` records into one task.

### R2. Give internal parent reasoning a usable result and an exact optional publication route

**Scenario.** A user asks the main Companion for a research answer. The parent delegates, finishes or is stopped, the child returns, and `request_parent` runs an internal synthesis. Section 7 forbids publishing plain text, correctly, but the API/UI matrix exposes child history/results and does not define how the synthesized parent result is found or how its explicit decision to answer reaches a real publication owner. The listed implementation slices can therefore pass the zero-implicit-speech assertion while leaving the useful answer in unaddressable `run_messages`.

**Actual owner evidence.** `chat-agent.ts:381-386` supplies non-primary settled text but performs no primary persistence. `run-prepared-publication.ts:29-43,60-68` requires a retained nonterminal accepted-work root and its trusted binding; primary lineage alone does not satisfy it. `prepared-publication-authorization.ts:20-29` registers a grant only after a trusted adapter owns real classification. `initiative-runtime.ts:95-117` is an existing Class B opportunity path with selection/policy, not a generic delayed response API. A concrete direct-request precedent exists in `co-watching/media-analysis-state.ts:78-89`: the accepted explicit request authorizes a bounded Class A result, while `media-analysis-runtime.ts:121-133` keeps its root alive through publication.

**Bounded correction.** Retain the internal inference default, and add the following joint contract rather than enabling automatic speech:

- Every parent continuation has an inspectable terminal result/disposition linked from the child completion and returned by the history/read model. A `no_action` result is a real disposition, not missing output.
- For direct-request reports, the trusted primary tool binding captures the exact original committed request and bounded reply purpose. Bind a proposed reply to that accepted purpose and a stable result/candidate identity. This authority is not inferred from `completionPolicy`, a model-supplied class, an arbitrary `parentRunId`, or every child created by an autonomous Run.
- Add one explicit final decision collector/sink for the new parent inference: retain internal result, no action, or propose a reply to an available captured reply authority. Its schema has no free publication class/authority fields. Streamed prose alone remains private.
- Name the adapter and its live accepted root. Either reuse a valid originating business accepted root or create the narrowly scoped direct-request report root through existing `admitAcceptedWork`/prepared-publication ownership. Keep that root alive through final publication; never repurpose/reopen the terminal original primary Run. Bind its purpose/expiry/currentness to actual request ownership and preserve it across ordinary parent stop as G4 requires. Unknown/lost restart authority waits for explicit continuation.
- A direct-request report can use the existing Class A mechanism for that proven response purpose. Work without that origin remains inspectable and must use an actually eligible existing Class B/business path for speech. Do not force it through WakeEngine or invent a blanket accepted-task exemption.
- Stage the explicitly selected canonical text and its source sidecar through DeliveryCoordinator, then retain `sent`, `unknown`, `no_target`, withheld/expired and internal-only outcomes separately. A later primary `inspect_subagent` call can still obtain the original child result through a real tool pair.

This is an ordinary implementation decision within the user's requested usable delegation behavior. It does not require reopening G1 or requesting permission to fabricate an acceptance label. If the proposed reply cannot be traced to actual permitted origin, the honest behavior is a readable internal result plus a refused publication disposition. Do not declare the complete generic user-request path delivered on that refusal-only fallback.

**Verification.** One complete direct-request path must exercise delegate, child completion after parent stop, internal parent synthesis, explicit reply decision, retained acceptance, delivery staging, source-aware Timeline replay and actual fake-transport outcome. In the matching no-action case, retain inspectable synthesis and create no speech. A forged/missing reply authority cannot publish. The read model must expose the continuation Run/result without requiring raw SQL inspection.

### R3. Include tool-acquired materials in the selectable, retained source set

**Scenario.** A fresh child is asked to read two documents through governed tools. Their titles/references are known only after the reads. It summarizes one. The proposed collector selects `{inputId, key}` from supplied materials, while native selected messages/tool results need not be converted to `ContextMaterial`. There is no stated producer/registration path for those newly acquired source descriptions. The result can therefore carry only generation origin, or an implementer may compensate by attaching every encountered tool source. Both miss the required general mechanism for this ordinary research path.

**Actual owner evidence.** `chat-agent.ts:407-415` executes captured tools under current Run/Attempt/Effect governance; `turn-mapping.ts:58-71,88-115` preserves native tool identity and output. The information is available at a real boundary. It is also vulnerable to later flattening: `context-reduction.ts:191-203` converts JSON/content results to bounded text; `:120-132` compaction rendering similarly bounds payloads. Merely preserving source metadata in an internal map does not make those later consumers aware of it.

**Bounded correction.** Extend the common material reference to address either an input-owned key or an actual retained tool-result-owned material key (exact Run/Attempt/tool-call or Effect identity). A capability may register its already-known optional source description beside its real governed result. Selected structured history can address its existing result identity without inventing a new call. Persist these associations with the existing private message/parts/source sidecar, not a global registry. Native framing remains sufficient when it already expresses the needed meaning; opaque outputs do not require invented semantic classification.

The result collector validates only selected references that actually occurred in this working context. It copies their known descriptions into the immutable result. The shared reduction API must preserve a source header with surviving associated content, or an honest omitted-content/reference trace; the program must not parse arbitrary prose and claim that inferred provenance is provider-known. Preserve text and error status so failed reads, unavailable sources and verified empty results remain distinct.

**Verification.** Read two synthetic sources during child execution, select one, and inspect the actual parent request, replay and compaction inputs. The selected material survives; the unselected source is not automatically attributed. Repeat after child reuse/restart and with an unknown-source tool. Include long structured output with source qualifiers in the middle, plus failed and empty read outcomes.

### R4. Make Co-Watching a concrete shared-child adapter before splitting Runtime and source writers

**Scenario.** S4 says to introduce reusable child preparation while retaining the accepted root, but its result consumer and control interaction are still only a sentence. Current preparation holds the Character lane, uses the accepted root's Run and controller, writes a revision-specific file, then validates that file before confirming the edit. Moving only the Agent call onto a generic child lane could remove foreground yielding, misclassify a user-paused child as preparation failure, or confirm the wrong file after an addressed correction. Keeping the current call untouched would leave the motivating path outside the new private transcript/control behavior.

**Actual owner evidence.** `co-watching/runtime-model.ts:53-84` owns output-path/revision construction, the shared Agent call, complete-plan validation and edit confirmation. `:87-131` owns foreground-yield recovery, registration and failure retirement. `runtime.ts:36-41,145-155,177-185` owns yield, revision cancellation and the Character lease. `task-workspace.ts:28-47` rejects incomplete/wrong-revision plans and preserves delivered candidates. Those are real contracts that a generic text collector does not replace. The root's publication/source binding remains necessary through `run-prepared-publication.ts:60-68`.

**Bounded correction.** Name a Co-Watching child binding containing the accepted root, exact child/work input, requested plan revision/output artifact, native material revision and generated-by identity. The adapter owns plan validation and source/edit/playback policy; SubagentService owns model execution, private transcript, inputs and exact cancellation. Retain the existing Skill/file plan protocol for this delivery, and define the result handoff explicitly: validated plan/artifact identity plus original child Run/Attempt is committed/readable before the adapter confirms the edit. A missing or invalid file produces a recorded domain failure, not an empty successful plan. The existing zero-bounded-moment branch remains a deterministic no-publication outcome with no model call.

Record these control cases in the adapter contract:

| Event | Required adapter behavior |
| --- | --- |
| Ordinary parent request stop | Neither accepted Co-Watching root nor child is stopped; original completion choice remains record-only. |
| New foreground reservation | Preserve the existing cooperative preparation yield and normal lease release. Treat this as temporary owner yield, not a user-stop latch or permission to replay uncertain effects. Resume only under current authority after foreground release. |
| User stops the child view | Persist the user latch and keep private context. Prevent the Co-Watching scheduler from automatically resubmitting/resuming that child. Keep the unfinished revision unavailable for publication; expose paused/blocked state instead of silently declaring successful preparation. Source expiry/retirement still applies independently. |
| User continues that child | Revalidate accepted source/revision/Host authority, then continue exact work under the shared service. A lost/retired source cannot be resurrected by the child control. |
| Parent requests a revision | Close the old output gate first; address the exact owned work or explicitly create replacement work. Only the matching validated revision can confirm the edit. Preserve delivered candidates. |
| Explicit Co-Watching stop or source retirement | Close publication and cancel the exact owned work. Do not clear a user latch, cancel sibling children or infer success from the last model Effect. |

No mandatory permanent child per feature is introduced. The normal parent-controlled generic API still supports choosing new versus existing working continuity. The adapter's default ownership of its accepted task is not a new feature-based reuse law.

**Verification.** A single isolated end-to-end fixture must show the Co-Watching preparation in the actual child read model, addressed revision, foreground yield, child stop/continue, original accepted-root publication, media/moment sidecar and later replay after disposal of transient plan files. Existing playback/source/delivery assertions must run through this adapter. SDK mock responses establish wiring only; owner playback and semantic acceptance remain pending separately.

## Accepted tradeoffs and bounded cautions

- **Retained child history without a new rolling-summary engine:** acceptable for this slice if bounded projection includes a truthful omission/reference and the usable history-read tool. Do not silently claim omitted work was inherited. Reuse the existing compaction coordinator only if an actual pressure case requires it.
- **User stop versus terminal notifications:** retaining the original `request_parent` policy for an honestly labelled cancelled/failed/unknown terminal report is consistent with separating stop scope and completion intent. It must not automatically resume that child or report success. The chosen all-terminal notification behavior should be documented and tested; it does not need another user preference interview.
- **Four-per-Character/sixteen-process concurrency:** these values have no measured capacity evidence in the proposal. They can be ordinary conservative initial scheduling defaults, not a claimed framework limit or product cap on child creation. Keep already accepted work durable, refill fairly on releases, reject a full pending-input buffer before acceptance with a typed outcome, and document queuing latency. Do not add arbitrary source/result truncation, feature quotas or cancellation to enforce them. Exact payload limits should reuse existing supported bounds where possible.
- **Historical retention:** source description survives as long as the associated speech/result, independently of transient task files. It does not grant current retrieval/publication rights. Preserve existing authorized deletion semantics; the new tables must participate where an existing owner deletes the associated Run/Character data. No new sweeper or deletion UI is required.
- **Prompt carriage versus semantic success:** the XML/native framing default is a reasonable reuse decision, not proof of attribution quality. Repeated compaction must retain source subject/corrections in generated prose. Mock summaries prove carriage only. Native Hindsight retain metadata is not proof that provider-owned extraction/reflection consumes it; that gap remains explicitly unverified rather than widening memory eligibility.
- **No evidence supports a framework replacement, global source registry, second permission authority or broad memory redesign.** None is requested by these corrections.
