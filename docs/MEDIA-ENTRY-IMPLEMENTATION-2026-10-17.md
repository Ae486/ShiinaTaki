## Independent URL analysis

An explicit analysis request admits an internal accepted-work root. Its captured tools resolve the target,
reuse a matching result/request, or submit one native request. Native waiting holds the existing root and releases
the Character lane. Completion uses the ordinary Character Agent and final settled text, then the existing generic
prepared-publication owner derives one Class A child for the requested result. The original root remains alive until
publication settles. Playback and Co-Watching consent are unnecessary. Cancellation never cancels unrelated work.

The result-generation execution narrows the existing governed tool bag to required reads; it cannot submit another
native job. This is a trusted per-execution selection over the existing SDK and governance, not another permission system.
This slice accepts supported Bilibili URLs. Local-file transport and other platforms remain separate work.

## Detected-viewing invitation

Actual fresh playback observations accumulate elapsed effective viewing, excluding seeks, pauses, buffering,
hidden non-PiP playback and unobserved gaps. Existing initiative policy and deterministic media eligibility run
before additional capture, access probes or model reasoning. The same Wake/InitiativeRuntime admits and claims the
opportunity. Captured governed access/capture evidence is acquired inside that admitted Run, appended to its ephemeral
control input, and judged by the same Character Agent. It creates no synthetic user message or detailed analysis.

Only a committed Class B invitation has accept/defer controls. Acceptance rechecks the exact current viewing and
starts the existing accepted Co-Watching flow; defer suppresses invitations for that viewing. Playback changes,
privacy withdrawal and expired authority invalidate pending offers. Explicit user requests retain their existing path.

The owner approved first-version defaults of 60 seconds of effective viewing, at least 120 seconds remaining,
a 120-second offer lifetime and no automatic invitation when duration is unknown. The three numerical parameters
use live settings in the existing registry and Home settings page. Numerical validation bounds are implementation
limits (positive values up to one day), not a change to the agreed default timing or initiative budgets.
