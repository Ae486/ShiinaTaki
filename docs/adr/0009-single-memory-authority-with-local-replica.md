# Memory has one authority; Hindsight mode uses a local replica and pending writes

Searchable memory has exactly one **Memory Authority** at a time: the Local Memory Provider when Hindsight is disabled, and Hindsight only after an initial import has completed and been verified. Enabling Hindsight does not create an active-active pair, and an outage never promotes the local store automatically; the local database remains a queryable **Memory Replica** for degraded recall, while new writes become **Pending Memory** and are submitted to Hindsight when it recovers. A write becomes durable memory only after the authority confirms it, at which point the replica is updated. This deliberately rejects automatic local failover and later conflict merging because availability is less important than preventing split-brain personal memory.

Replica synchronization is asynchronous and normally incremental. Chat, recall, and authoritative Hindsight writes do not wait for a replica refresh; the previous verified local snapshot remains readable while a background worker applies a batch transactionally and advances a durable replication checkpoint only after the batch succeeds. Consequently, degraded recall is guaranteed to reflect the last successful checkpoint, not necessarily the authority's most recent unsynchronized change.

Both automatic and manual synchronization are supported. Routine synchronization transfers only changed or deleted memory entities: Taki-originated operations can identify the affected Hindsight document or memory-unit IDs directly, while changes initiated through Hindsight itself require a monotonic change journal and cursor so the replica can resume without timestamp ambiguity or offset-pagination drift. Hindsight's audit log may support an initial integration, but it is not the long-term correctness contract. A full import remains necessary for first enablement. A logical full reconciliation runs asynchronously every seven days by default, with a user-configurable interval and an immediate manual action; it compares the complete authoritative identity, revision, lifecycle, and integrity manifest but transfers and repairs only divergent records. This detects drift, recovers from an expired cursor, and validates integrity without recopying an unchanged bank.

Advanced users may modify authoritative memory directly through Hindsight's Control Plane or MCP surface. Those writes are not a separate authority: they must enter the same Hindsight change journal and be consumed by Taki's replica synchronizer. Local edits made while Hindsight is authoritative remain local-only administrative state and must not overwrite Hindsight; they can be submitted explicitly through a Taki operation if the user intends to change the authority.

Hindsight uses a two-level bank topology for each Taki user: one **Global Memory Bank** shared by all Characters and one **Character Memory Bank** for every Character-user relationship. A Memory Layer remains Taki policy metadata inside the appropriate bank rather than becoming a bank of its own. Recall queries the global bank and the active Character's bank in parallel, then merges and deduplicates their results before applying Taki's visibility, retention, and prompt-assembly policies. Other Characters' banks are excluded by default. This preserves character isolation and independent reflection without fragmenting Hindsight's learning across one bank per layer.

Every foreground user response performs **Automatic Memory Recall** by default. The current user input queries the Global Memory Bank and active Character Memory Bank in parallel at low budget; Taki merges, deduplicates against already-visible memory, and projects the useful results into one ephemeral per-run section under a shared configurable result and token cap, initially 1024 tokens total. This section is never persisted into the conversation timeline or returned to the Write Gate or Retain. A partial bank failure preserves results from the other bank, and complete recall failure records provider-health diagnostics but does not fail the chat turn. Local authority uses the local retriever, healthy Hindsight authority reads Hindsight directly, and an outage uses the last verified Memory Replica plus an explicitly unconfirmed Pending Memory overlay. Explicit `recall` and `reflect` tools remain available for deliberate higher-budget investigation. This hybrid design intentionally supersedes T5-R6's tool-only retrieval because models do not invoke memory search consistently, while retaining agent-directed investigation for questions that exceed the automatic budget.

Layer classification in Hindsight mode is a two-stage process. Retain extraction assigns a controlled `taki-layer:*` label to each extracted fact, using Hindsight's per-fact entity-label mechanism rather than document-wide metadata so one input may produce facts in different layers. The controlled vocabulary includes `unclassified` as a safe fallback. Later policy maintenance reviews only unclassified or demonstrably incorrect assignments; ordinary facts do not incur a second classification pass. Classification must precede observation consolidation where possible so derived observations are created in the correct scope.

Memory maintenance is provider-specific rather than duplicated. Local mode keeps the existing full Taki tidy pass. Hindsight mode disables that generic pass and delegates extraction, semantic consolidation, observation evolution, mental-model refresh, graph repair, and fact curation mechanics to Hindsight. A reduced **Memory Policy Curator** remains responsible only for Taki-specific layer, visibility, retention, and Memory Block projection rules. It evaluates changed or exceptional memories rather than rescanning the whole bank, and every durable edit, invalidation, restoration, or reclassification goes through Hindsight; the local replica is never a mutation target.

Automatic ingestion remains subject to Taki's **Write Gate** in both provider modes. In Hindsight mode the gate is deliberately limited to eligibility and ownership routing: in one decision it reviews a committed conversation span using the behaviour-change test and returns keep or skip, the exact source boundaries needed for provenance, and `global`, `character`, or `both`. Global means the source contains user-wide knowledge that should survive Character changes; character means it belongs to the active Character-user relationship; both is reserved for spans that genuinely contain each scope. This routing is Taki policy rather than semantic memory extraction, and it adds no second gate call. The gate must not generate a replacement summary, extract candidate facts, assign Memory Layers within a bank, deduplicate, or perform semantic consolidation.

When the gate passes, Taki submits the original eligible user-and-Companion span, timestamps, Character identity, and safe provenance only to the selected bank or banks after removing system instructions, injected recalls, hidden prompt material, secret-bearing or oversized tool payloads, and other feedback-loop content. A `both` result uses deterministic, bank-specific document identities so retries remain idempotent while each bank's template extracts only its own scope. Hindsight then owns one-to-many fact extraction, entity and layer labels, embeddings, source links, observations, and later maintenance. An explicit user request to remember something bypasses eligibility filtering but still uses the same ownership router. A later detected ownership mistake is repaired by copying the authoritative source or fact into the correct bank and reversibly invalidating the misplaced fact, with provenance preserved. Gate execution remains detached from chat; a gate or Retain failure is durably retryable and never turns an eligible source into a silent loss.

Individual memory mutation is not importance-gated. The foreground Companion and the Memory Policy Curator may autonomously edit, invalidate, restore, or reclassify any individual memory regardless of its authorship, layer, or interaction impact. This deliberately accepts occasional interaction drift because memory is revisable internal context and a later user correction can immediately revise the authoritative memory again. Retirement uses reversible Hindsight invalidation by default. Permanent deletion and bank-wide clearing remain explicit user or Control Plane operations because their irreversibility and blast radius differ from ordinary memory correction; deterministic machine-data retention such as expired captures may still hard-delete under a declared lifecycle rule.

The Memory Replica is a full-fidelity logical projection, not a physical copy of Hindsight's PostgreSQL schema. It stores the provider-stable identities and recall-relevant state for banks, source documents when retained by policy, world and experience facts, observations and their source provenance, lifecycle state, tags and Taki layer labels, timestamps, mental models, directives, and per-bank Replica Checkpoints. Hindsight worker queues, credentials, internal indexes, and other operational tables are not mirrored. A derived and rebuildable FTS/BM25 index is always available. A local vector index is an optional enhancement built asynchronously only when the user configures an embedding model; when enabled, recall combines semantic and sparse results, while missing configuration, model failure, or an incomplete rebuild transparently leaves sparse recall operational. Hindsight enablement and ordinary memory operations never depend on the local vector index. Markdown is an optional human-readable export rather than the synchronization substrate.

The existing Markdown entry format is retired as active storage for both provider modes. Local and Hindsight adapters exchange **Canonical Memory Records** aligned with Hindsight's public logical model while remaining independent of its private database schema. A compatibility normalizer accepts every supported historical Markdown/frontmatter variant and converts it deterministically before any authority mutation. A full dry-run preflight parses and validates identifiers, ownership, layers, timestamps, lifecycle, content size and hashes, reports the exact exceptional sources it cannot normalize, and performs no partial cutover. A supported, well-formed legacy entry failing this path is an implementation defect to fix, not an expected condition for the user to work around.

During migration, each normalized legacy entry becomes a source document with a deterministic document ID, original entry ID, layer, timestamps, content hash, and preserved raw-source reference; Hindsight may then extract multiple independently classified facts. The durable **Memory Migration Ledger** records `legacy entry → canonical source → document operation → fact IDs`, terminal status, attempts, and diagnostics. Imports are resumable and idempotent, retry transient operation failures without duplicating documents, and verify source completeness rather than misleading count equality. Original Markdown is preserved as a read-only migration snapshot until verification and remains available for explicit export, but edits to it never mutate authoritative memory.

Hindsight cannot become the Memory Authority while any non-excluded source lacks a successful terminal ledger result, while any imported document operation or derived fact mapping is unresolved, or while the resulting local replica and checkpoint fail integrity checks. Exceptional corrupt or unsupported sources remain visible with their raw content and exact reason; only an explicit per-source user exclusion can remove them from the required set. The authority switch is atomic after all requirements pass, so a failed or interrupted migration leaves Local authoritative and can resume from the ledger without rollback repair.

Taki provides a guided Hindsight setup without embedding Hindsight into the application distribution. The wizard can provision a supported local deployment or connect to an existing instance, validate prerequisites and storage, configure deployment-level models through Taki's secret-safe settings, test database and model health, create the global and Character banks from versioned Taki bank templates, and preview the initial import. Every supported Hindsight connection requires API-key authentication, including loopback-only deployments; Taki-managed provisioning enables authentication, and the connection wizard refuses an unauthenticated instance rather than treating local network placement as an authorization boundary. The credential is stored only through Taki's secret-safe configuration and is never written into memory records, the replica, exports, logs, or template manifests. Hindsight remains independently operable and upgradeable, and it does not become the Memory Authority until authenticated health checks, the initial import, logical replica build, integrity checks, and user-visible verification all succeed.

Each **Taki Bank Template** is an additive profile rather than a replacement memory engine or copied prompt bundle. Configuration precedence is Hindsight's native behavior, then the versioned Taki overlay, then explicit user overrides. Separate Global and Character templates add only the project-specific extraction focus, controlled `taki-layer:*` labels, bank perspective, relationship continuity, observation goals, reflection framing, directives, and mental-model definitions appropriate to that scope. Native additive seams such as `retain_mission`, `reflect_mission`, entity labels, directives, and template-managed mental models are used directly. Hindsight's current `observations_mission` replaces the built-in consolidation rules rather than extending them, so the supported local Hindsight fork adds a narrow additive observation-instructions seam; Taki must not freeze and copy Hindsight's full default consolidation prompt merely to append project guidance. Template and user-override revisions are tracked separately. An upgrade may preview and apply a newer Taki overlay, but never silently overwrites user customization, and removing an overlay restores inherited Hindsight behavior.

Taki maintains Hindsight compatibility as a minimal extension or patch series rather than a separately evolved full fork. A versioned compatibility manifest declares the supported Hindsight release range and the required public API, change-journal, template, and additive-prompt extension contracts. Before replacing an authority instance, the setup manager snapshots its banks and configuration, starts or connects to the candidate version without switching authority, runs authenticated health, migration, contract, retain/recall, synchronization, and template-overlay checks, and switches only after they pass. An unsupported or failed candidate leaves the existing authority running and is never adopted speculatively. Small generally useful extension points should be proposed upstream where practical, while Taki-specific policy remains in the external template and adapter layer.

Model setup uses progressive disclosure. The basic path asks for provider, base URL when applicable, credential, and one default model inherited by retain, reflect, and consolidation. Advanced settings may override those operations independently and configure embedding and reranking. The first implementation stops at validated fields, connectivity and operation health checks, and actionable diagnostics; provider-specific workarounds are added only from reproducible setup failures rather than anticipated in advance.

Agent-facing memory tools use one **Memory Tool Contract** aligned with Hindsight's public retain, recall, reflect, edit, invalidate, and restore semantics. Local adapters implement the same names, fields, lifecycle states, and stable identifiers where possible; Hindsight adapters delegate to the authoritative API. The foreground Companion may use every individual-memory operation without an importance- or authorship-based confirmation gate; only bank-wide administration, bulk clearing, and permanent deletion are withheld as Control Plane operations. Runtime capability metadata identifies the active provider and supported optional operations, while prompts explain only contextual differences. Every call carries an operation/request identity when asynchronous and returns structured error information (category, retryability, authority state, and next action); adapters never silently switch authority or hide a failed write.

The canonical Hindsight-aligned tool names replace the current `memory_write`, `memory_search`, `memory_archive`, and maintenance names on the model-facing surface immediately when this migration lands; new prompts, tool listings, and capability metadata never advertise both vocabularies. A non-advertised compatibility adapter may translate legacy tool-call records, imported prompts or skills, and transition-period invocations into the canonical schema without rewriting the stored timeline. Translation emits telemetry identifying the legacy caller and returns the canonical lifecycle and error envelope. The aliases are removed after migration diagnostics show no remaining executable legacy callers; historical timeline rows remain readable as historical events and do not require the old tools to stay registered indefinitely.

A temporary Hindsight outage never changes authority. Confirmed reads use the last complete Memory Replica, while all new write intents are stored durably as Pending Memory with idempotency keys, original timestamps, target revisions where applicable, and enough provenance to replay. Pending Memory may be included as an explicitly unconfirmed overlay during degraded recall without being merged into the confirmed replica. On recovery, Taki verifies the Hindsight instance and bank lineage, pulls and applies every authoritative change after the last Replica Checkpoint, then replays each pending operation with optimistic revision checking. A new retain has no target revision and is submitted normally. An edit, invalidation, restoration, or reclassification is applied only when its recorded target revision still matches the authority; a changed or missing target causes that Pending Memory to be marked `superseded` and retained for audit, with no merge, overwrite, or user-resolution workflow. Replay remains idempotent and one superseded operation never blocks the rest. Taki verifies the actual native write result, pulls its committed factual changes, and may complete that pending write after the local replica has transactionally applied those changes through a verified checkpoint. Unknown native outcomes remain unresolved and are never blindly replayed. Hindsight's observation and mental-model maintenance may continue in the background, with later authoritative changes consumed by ordinary synchronization. Therefore write confirmation proves durable factual application, not that every derived summary is current; a recoverable outage still preserves independent new memories and non-conflicting mutations.

This avoids changing native maintenance scheduling solely to finish routine recovery. Derived progress is separate and uses actual provider evidence, or remains explicitly unknown when unavailable. The independent completion and integrity gates for initial activation and a healthy provider switch remain mandatory; zero Pending Memory is not proof that those gates passed. If the configured Hindsight authority is confirmed permanently unavailable, the user may explicitly perform an Emergency Local Takeover after repair and backup recovery options have been exhausted. Taki snapshots the replica, outbox, and checkpoints; presents the potentially missing remote-only interval; and requires explicit confirmation before starting a new Authority Epoch with Local as authority. A former Hindsight instance that later reappears is treated as a foreign historical branch and is never merged or promoted automatically.

A healthy, voluntary switch from Hindsight back to Local is a planned authority migration rather than an emergency toggle. Taki first verifies the Hindsight lineage and health, drains accepted operations, verifies the derived maintenance required by the cutover contract, performs a final incremental synchronization followed by full logical reconciliation, and requires zero Pending Memory and no known replica difference. A short cutover fence queues new memory mutations while Taki snapshots the reconciled replica and checkpoints, creates a new Local Authority Epoch, promotes that snapshot to the Local Memory Provider, and then replays the fenced mutations against Local before reopening ordinary writes. The previous Hindsight instance becomes a read-only historical authority branch and cannot overwrite the new epoch. Re-enabling Hindsight later is a fresh Local-to-Hindsight migration that imports every mutation from the current Local epoch before another atomic authority switch. If Hindsight is unhealthy or reconciliation cannot complete, the ordinary switch is unavailable and the user must use the explicit Emergency Local Takeover flow with its missing-data warning.

Automatic replica synchronization uses fixed-interval Change Cursor polling rather than event notifications. The default interval is six hours and is user-configurable; it therefore also defines the ordinary worst-case age of the confirmed replica if Hindsight becomes unavailable immediately before a scheduled poll. Manual incremental synchronization remains available, and low-frequency full reconciliation detects cursor or implementation drift. This trade-off is acceptable because healthy Hindsight-mode turns read from the authority directly, while Agent Context normally preserves recent interaction across the configured interval if an outage occurs before the next poll. That continuity is a mitigation rather than a correctness guarantee: external Control Plane changes and background Hindsight derivations may not exist in the active conversation, so the UI must expose the configured interval, next poll, last attempt, last successful checkpoint, current lag, pending count, and latest error.

The scheduler persists its next-due time. If Taki was stopped or disconnected when a poll became due, the next successful startup or reconnection performs one immediate catch-up poll rather than restarting a fresh six-hour wait or stacking every missed interval. After a successful catch-up, the next interval is calculated from that success.

While automatic synchronization is enabled, a failed incremental synchronization enters a persisted retry schedule of one minute, five minutes, fifteen minutes, one hour, and then every six hours until recovery. Only one synchronization attempt may run at a time. Any successful synchronization clears the consecutive-failure state and schedules the next ordinary interval from that success. An explicit immediate synchronization, or a verified startup or Hindsight reconnection, may run before the current backoff expires rather than waiting unnecessarily. Manual synchronization mode does not create background retries after a failed user-triggered attempt.

The settings UI exposes the synchronization mode, incremental synchronization interval, full-reconciliation interval, current state, last attempt time, last successful checkpoint time, last full reconciliation time, pending change count or replication lag, consecutive failure count, next retry or ordinary poll time, latest error, and actions for immediate incremental synchronization and full reconciliation. Manual mode is allowed to become stale and must present that state explicitly; automatic mode is the mode intended to keep the local replica near the Hindsight authority while Hindsight is healthy.
