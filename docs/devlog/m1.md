## Issue #4 — 设备身份与配对（已收官 2026-07-09）

**目标**：WS 协议的安全与拓扑地基——connect 握手、配对码引导、token 重连、operator/node 角色强制；协议零 localhost 假设。

**交付**：connect schema + `-32000` 应用错误码路径 + 5 个新错误码；core 的 `devices/`（文件化注册表，token 仅存 sha256、`timingSafeEqual` 比对、角色配对锁定）、connection-registry、pre-auth 门（fail-closed）、方法级角色门；CLI 身份文件 + 配对码交互 + 竞态安全 REPL（`repl.ts` LineQueue）。提交：`2f93c4b` / `ec4e8a7` / `8911398` / `a12542b`。

**验证**：6/6 验收标准实证；123 测试三门全绿；三腿真实冒烟：首连出码→输码→聊天 / token 重连（跨 core 重启）/ 篡改 token → `AUTH_FAILED` exit 1。

**要点捕获**：主脑亲验抓到子代理未发现的真缺陷——管道 stdin 即时 EOF 时 readline 事件在消费者挂载前丢失致 REPL 永久挂起（裸 WS 探针一步定责 client 侧）；check 裁决两项已入规范：应用级拒绝永不复用信封错误码、pre-auth fail-closed/认证后 fail-tolerant 非对称原则；v1.5 加固遗留：配对码无速率限制（见 #29 届时评论）。

**人工验收项**：无。
