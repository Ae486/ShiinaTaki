## Issue #7 — 自动记忆写入（已收官 2026-07-10）

**目标**：时间线不再静默遗忘——每 20 消息的情景小结写入 episodes 层;回放窗口（200 条）边界处的预压缩冲洗:一次静默的带工具 agent 回合,从即将滑出上下文的片段中提取持久记忆;双写守卫。

**交付**：迁移 003（`memory_auto_state` 水位线表,即双写守卫本体）+ `db/memory-auto-repo`;`memory/` 新增 auto-memory 编排器（每角色 promise 链互斥、失败隔离、警告后自然重试）、episodic-writer（非流式 generate → 1-3 条摘要）、flush-writer（静默工具回合,输出弃置、零时间线行、零 WS 事件）;chat-agent 仅加一个可选依赖 + 一次回合后分离调用。

**验证**：282 测试三门全绿;活体冒烟——11 轮真实对话跨过阈值后情景写入器**恰好触发一次**,3 条中文摘要落盘（含正确 frontmatter）,事件日志仅含 `count/from/to`;对话中模型同时主动调用了 memory_write（根计数器 id 错位为证)——自动与显式两条写入路径并行无冲突。冲洗路径（需 200+ 消息）由 T5-T8 测试覆盖,未做活体验证。

**要点捕获**：check 修复 1 项 HIGH——情景事件日志曾输出 entryIds,而 id 的 slug 就是内容片段,违反"日志零记忆内容"规则（降级为 layer+count+区间）;三触发互斥补测锁死 promise 链清理逻辑。**运维根因确认**:反复出现的 8974 孤儿进程来自子代理自检时经 pnpm 启动 core——常备令升级:代理启 core 必用随机端口 + 进程树清理;主脑冒烟前必查杀端口。

**人工验收项**：无。
