**目标**：灵魂基座——层泛型引擎（store/indexer/retriever/assembler）+ 声明式层注册表;文件即真相、SQLite FTS5（trigram,CJK 安全）为可重建索引;LLM 获得首批工具（memory_write/search/archive）;逐回合确定性上下文装配,钉住的承诺永不截断。

**交付**：`memory/` 模块 19 个文件（注册表/前言解析/store/索引器/检索器接口+FTS5 实现/装配器/工具,粒度良好全部 <300 行）;迁移 002（memory_entries + FTS5 trigram 虚表）;chat-agent 升级为 per-turn agent 构造（装配 instructions + characterId 闭包工具）;零新依赖（手写前言子集 + 双域 token 估算器 + CJK slug）。

**验证**：260 测试三门全绿;真实 DeepSeek 活体冒烟三阶段——(1) 中文 "记住我们的约定：每周五晚上一起看电影" → 模型主动调用 memory_write,文件落盘 `relationship/0001-….md` importance 10;(2) 重启 → 调和 total:1 → 钉住块回忆成功;(3) **决定性实验**:删除整个 taki.db（时间线+索引清零）仅留 markdown → 重启零历史下依然答出约定——files-as-truth 闭环实证（AC 2 活体版）。

**要点捕获**：check（fable）修复 2 个真缺陷——HIGH:用户手放的坏 .md 文件会让 core 启动崩溃（现降级为调和报告 invalid 列表）;MEDIUM:意图门误匹配 5 消息窗口而非当前消息。三项 impl 自报偏差全部证据化祝福,其中 bm25 列偏移被证明是"无测试守护的承重墙"（错位即静默颠倒排序）,已补翻转即失败的钉子测试。FTS5 整句引用对"查询是记忆超集"场景命中为零 → 重叠三元组分解为正解（OR 语义 + IDF 保精度,注入安全经对抗测试）。

**运维教训（再犯即流程缺陷）**：pnpm 包装的后台 core 被停止时孤儿化 node 子进程占端口 8974,本任务两次冒烟被此坑扰——已升级常备令:每次冒烟启动前必查杀端口占用;冒烟一律裸 node 直启。

**人工验收项**：无。

## Issue #7 — 自动记忆写入（已收官 2026-07-10）

**目标**：时间线不再静默遗忘——每 20 消息的情景小结写入 episodes 层;回放窗口（200 条）边界处的预压缩冲洗:一次静默的带工具 agent 回合,从即将滑出上下文的片段中提取持久记忆;双写守卫。

**交付**：迁移 003（`memory_auto_state` 水位线表,即双写守卫本体）+ `db/memory-auto-repo`;`memory/` 新增 auto-memory 编排器（每角色 promise 链互斥、失败隔离、警告后自然重试）、episodic-writer（非流式 generate → 1-3 条摘要）、flush-writer（静默工具回合,输出弃置、零时间线行、零 WS 事件）;chat-agent 仅加一个可选依赖 + 一次回合后分离调用。

**验证**：282 测试三门全绿;活体冒烟——11 轮真实对话跨过阈值后情景写入器**恰好触发一次**,3 条中文摘要落盘（含正确 frontmatter）,事件日志仅含 `count/from/to`;对话中模型同时主动调用了 memory_write（根计数器 id 错位为证)——自动与显式两条写入路径并行无冲突。冲洗路径（需 200+ 消息）由 T5-T8 测试覆盖,未做活体验证。

**要点捕获**：check 修复 1 项 HIGH——情景事件日志曾输出 entryIds,而 id 的 slug 就是内容片段,违反"日志零记忆内容"规则（降级为 layer+count+区间）;三触发互斥补测锁死 promise 链清理逻辑。**运维根因确认**:反复出现的 8974 孤儿进程来自子代理自检时经 pnpm 启动 core——常备令升级:代理启 core 必用随机端口 + 进程树清理;主脑冒烟前必查杀端口。

**人工验收项**：无。

## Issue #8+#9 — MCP 客户端 + Skills 加载器（合并任务,已收官 2026-07-10）

**目标**：agent 的两个可插拔扩展面——MCP 客户端（stdio + Streamable HTTP,经 `@ai-sdk/mcp`,ADR 0006 唯一子进程豁免点）+ 每次 MCP 工具调用过操作员审批门（once/session/always/never 记忆）;Skills 加载器（SKILL.md 发现 + `load_skill` 工具懒加载 + 启停持久化）。

**交付**：`@taki/shared` 审批协议帧;core 新增 `mcp/`（config/connect/manager,命名空间 `${server}_${tool}`,execute 包装为 `{ok:false}` 信封）、`approval/`（broker 挂起表 + 超时即拒 60s / decision-store 元组键持久化 / gate 策略模块——M3 权限门的直接复用接缝）、`skills/` 四件套;审批走 **v7 原生 `toolApproval` 异步函数**（研究实证:单次 stream 内联等待,拒绝时 SDK 自动喂模型 `execution-denied`）;WS 腿零信封改动（`approval.request` 通知 + `approval.respond` 方法 + approvalId 关联）;CLI 审批提示（y/s/a/d/n）。零新依赖(@ai-sdk/mcp 属钉定栈)。

**验证**：344 测试三门全绿(新增 62);活体冒烟三阶段——(1) 全新数据目录四服务器配置:死服务器降级警告跳过、其余 3 台连通发现 3 工具;stdio 工具审批后执行(`echo: pineapple`)、**HTTP 传输工具**审批后执行(2+3=5)、skill 懒加载后模型严格照章("Captain"+"STARLIGHT");(2) 重启:token 免配对重连,`always` 免审批直执行,`once` 正确未持久化;(3) 指名 `fixture2_echo`(独特回复前缀实证到达):**尽管 fixture 已 always,fixture2 照样弹审批**(per-server 隔离),拒一次→未执行且模型优雅续话→再调再弹(deny-once 不记忆)→session 批准执行。

**要点捕获**：check（fable,安全边界例行升格）修复 2 项——**HIGH:无 TurnContext 时审批接缝默认 fail-open**(今日不可达,但 M5 调度器一接入即全绕过;已翻转为无操作员即拒,钉子测试锁死)与 MEDIUM:decision-store 键用裸 NUL 字节分隔(改 JSON 元组,可证注入安全)。四项 impl 自报偏差全部祝福(approval-gate 独立模块 = M3 换芯点;mcp-connect 单文件化 ADR 0006 豁免)。冒烟一度误判 per-server 隔离失效,复测证明是**模型自选了已获批的同名工具**——工具选择行为,非门缺陷;教训:同脚本多服务器的冒烟必须让回复可区分。规范沉淀 2 条:状态文件损坏策略非对称(认证 fatal / 扩展 warn+降级)、审批门全非肯定路径 fail-closed 且默认值需翻转即败测试。

**人工验收项**：无新增（CLI 审批交互已由主脑活体验证;设置 UI 管理入口属 M5 #25）。
