## Issue #12 — exec 能力 + 完整治理管线（收官 2026-07-11，待人工活线冒烟）

**目标**：通用 shell 执行 `exec` —— v1 最高危安全边界。TS Core 永不 spawn;exec 请求跨 WS 到 Rust Shell,由 Shell 解析、裁决策略、spawn、审计。解析器与策略引擎穷尽 table 驱动测试(ADR 0002)。走 #10/#11 已证门路径,无新架构。

**关键裁决(三项经用户拍板 + 主脑依不变量定 14 项,全固化于 prd R0-R17)**：
- **cwd(R0,ADR 0007 Stance A)**:exec 在 Node 侧(宿主机)执行,cwd 由 Shell 解析——单机默认指向 Workspace,双机走 Shell 自有目录,**永不假设 Core 文件系统**。这催生了新 ADR:详见下。
- **审计记命令(R9,用户定 2A)**:exec 审计行**含命令原文**,作为记录在案的 exec 专属例外(命令是"动作记录",是 Windows 无沙箱下 ADR 0002 依赖的爆炸半径凭据);其余能力仍只记名字(`skip_serializing_if` 保证字段省略)。
- **黑名单可编辑(R11,用户定)**:种子集为内置默认,operator 经 `exec-policy.json` 的 `blocklist` 增删,case-insensitive 合并。
- 主脑裁定:解析器手写零依赖(crate 检测不了操作符)、`.exe`-only、`.bat`/`.cmd` 与 shell 类(cmd/powershell/pwsh/bash/sh/wsl)永不自动跑、glob 升级审批、gate **Shape B**(`evaluate_exec` 与 `evaluate` 并存,门仍是唯一审批+审计权威)、`full`=一律审批、exec **一律弹窗不持久化**(按能力记 always=全绕过=禁止)、默认 allowlist 空(fail-closed)、环境白名单从空拷贝(剥离所有 API key)、超时**手写 try_wait 轮询**(零依赖,弃用 wait-timeout)、直接子进程杀(树杀留 M4)、1 MiB/流 + 30s。

**交付**：`@taki/shared` `ExecOutputSchema`(opaque payload,镜像 Rust serde + 3 金样夹具双向断言);core `exec-tool.ts`(镜像 shell-open:execute 永不抛、`{command}` 透传、命令/输出绝不记日志);Shell 按尺寸上限拆 `capabilities_impl/exec.rs` + `exec/{parser,policy,sandbox}.rs`——parser 纯分类三段筛、policy mode 逻辑 + 种子黑名单 + load-or-degrade-safe 配置、sandbox 无 shell argv spawn + 环境擦洗 + 手写超时杀 + 双线程 cap 读取;gate 加 `ExecClass` + `evaluate_exec`;audit 加 exec-only 命令字段;lib.rs 一注册 + 一 vec 项(不变量 7)。零新依赖(Rust 与 npm 运行时皆无;shared 加 `@types/node` 仅 devDep,测试读 fixture 用)。

**验证**：六门主脑亲验全绿——444 TS 测试(shared 125 / core 301 / cli 18)+ **59 Rust 测试**(src-tauri 26→59)+ clippy --all-targets 零警告 + frontend build。解析器 table 覆盖每条 SIMPLE/ESCALATE/BLOCK 支路(含"链中 BLOCK 取胜"顺序证明、`.bat`/`.cmd`、argv[0] 为 shell、glob、引号失衡);policy mode 矩阵 deny/allowlist/full × {simple/非白名单/链式/黑名单};gate Shape B 表(approver 见命令、exec 永不持久化);audit 断言命令仅 exec 有。**三个真实 Windows spawn 测试**(`#[cfg(windows)]` 门控,非伪造):快速 exe exit 0、`ping -n 30` 超时被杀 exitCode null、4字节 cap 截断被杀。#10/#11 的名键 `evaluate` 路径与只记名字审计测试字节级不变。

**主脑逐行亲读五个安全核心 + fable 独立对抗 check 双重验证**:解析器逐字符原始串扫描,构造不出任何"带真实操作符却返回 SIMPLE"的输入(`a>b` 无空格被 `>` 命中);`evaluate` 字节未变;审计只对 exec 记命令;sandbox 环境从空白名单拷贝无 API key 泄漏、argv 无 shell、超时真杀。check 判 SHIP、0 缺陷。主脑修一处对裁定的偏离:R11 明列"HKLM 强写"入种子,实现漏了 `reg add HKLM /f`,已补(policy.rs 种子 + 测试)。

**已裁定接受的残留(记此备案,M4 候选)**:(1) `sandbox.rs` 若被批命令派生孙进程继承 stdout 句柄,直接子进程被杀后读线程会阻塞至孙进程退出——树杀延期(R14/ADR 0002 无沙箱)的后果不止孙进程存活、还可能卡住响应,M4 加有界 reader-join;(2) 全路径 basename 匹配:`C:\evil\git.exe` 在 `git` 允许时会自动跑——全路径解析属 M4 加固;(3) 黑名单为子串匹配的 tripwire(非边界),`format d:` 等可绕过,但边界是 allowlist + 一律询问,且默认空 allowlist 下一切升级审批。

**架构衍生物 —— ADR 0007**：R0 的 cwd 之争暴露了"单机/双机部署下能力与数据位置"这一真实岔路,已立 ADR 0007 采纳 **Stance A**(宿主机是 agent 的世界,VPS 纯算力外包;OS/数据类能力都在 Node 侧执行;v1 单机照常出货,双机 v1.5 可选、文件能力届时从 Core 侧迁为 Node 路由)。详见 `docs/adr/0007`。

**人工验收项**:追加至 manual-checks.md(exec 自动跑允许命令、链式/危险命令弹窗显示命令原文、灾难命令直拒、超时、工作区 cwd)。

## Issue #11 — 类型化能力：进程列表 / 剪贴板 / shell-open / 工作区文件（收官 2026-07-11，待人工活线冒烟）

**目标**：在 #10 已证的门路径上做宽度扩展——四个类型化能力,无新架构。process-list（sysinfo,只读快照）、clipboard 读/写（arboard,纯文本）、shell-open（tauri-plugin-opener,URL/路径启动）走 Shell 门路径;工作区文件读/写走 **Core 侧 TS**（不变量 2:Core 是工作区唯一写者;不变量 8:VPS 拓扑下 Shell 异机——文件能力若在 Shell 侧会读错文件系统）。

**关键裁决（主脑依不变量定夺,无一需用户拍板）**：(1) workspace-files = Core 侧 node:fs 工具 + 自带围栏,NOT Shell 门能力（4 个里的特例）;(2) `CapabilityOutput` 泛化为 opaque `Value`（Option A,与 `input: z.unknown()` 对称,保不变量 7——加能力只碰自己模块);(3) shell-open 用 `{kind,target}` 显式 schema + http/https/mailto 白名单;(4) **主脑加固**:审批弹窗必须显示 shell-open 目标(`Gate::evaluate` 加 `detail: Option<&str>`,只进弹窗不进日志)。

**交付**：`@taki/shared` capability-outputs（每能力自持 output schema,镜像 Rust serde)+ respond output 转 opaque;core 四个 Shell 工具（process-list/clipboard-read/clipboard-write/shell-open,经 route-capability 共享 find-node+broker 路由)+ workspace/（workspace-paths 围栏算法 + read/write-file 工具 + fs-error errno 提取);Rust 三个 exec（process_list/clipboard/shell_open）+ gate detail 接线;CI 无变。三新 crate:sysinfo 0.39 / arboard 3.6 / tauri-plugin-opener 2。

**验证**：四门主脑亲验全绿——438 TS 测试（shared 122 / core 298 / cli 18)+ 26 Rust 测试 + clippy --all-targets 零警告 + frontend build。**工作区路径逃逸防御**（AC4 安全核心）table-driven 覆盖:`../../` / 绝对路径 / 盘符相对 `C:foo` / ADS `foo:hidden` / 保留名 `NUL` / NUL 字节 / **真实创建符号链接指向外部**——realpath 双向规范化 + 组件级 `path.relative` 前缀比对(非字符串前缀,`/workspace-evil` 不匹配 `/workspace`),翻转即败。金样夹具补齐截图 payload 跨语言双向断言(泛化时曾丢失)。

**要点捕获**：check（fable,安全边界升格）修复 2 项——MEDIUM:read/write-file 把内嵌绝对路径的 Node fs 错误原样泄给模型(违反"路径永不泄绝对前缀");MEDIUM-LOW:`resolve()` 对词法干净但含 NUL/ENOTDIR 的输入会 throw,逃到外层 catch 二次泄路径,违反模块永不抛契约(现包为结构化 `INVALID_PATH`)。顺手补回泛化时丢失的截图金样、正名 Rust `CapabilityOutput`→`ScreenshotOutput`、route-capability 的 code 收紧为闭合联合。**shell-open 的 `kind:"path"` 残留风险(已裁定接受,记此备案)**:ShellExecuteW 对路径形字符串也会解析协议处理器,故 `{kind:"path", target:"ms-settings:"}` 能绕过 URL scheme 白名单启动处理器——白名单只约束 url 臂,path 臂的安全 100% 依赖 ruling 4 的 always-ask + 弹窗逐字显示目标。这是 M4 若给 path 臂加约束的候选点。

**环境插曲**：本机 rustc 1.88 编不动 sysinfo 0.39.6（patch 级 MSRV 抬到 1.95)。主脑裁定升级 rustc（CLAUDE.md 本就规定 `rustup update stable` 且钉下限;CI 用 @stable 本就更高)→ 1.97.0,并暴露一个仅编译可见的测试期错误(`OpenPlan` 缺 `#[derive(Debug)]`,`expect_err` 需要),已修。`src-tauri/Cargo.toml` rust-version 修正 1.88→1.95。**待用户确认**:CLAUDE.md 工具链表宜同步为 >= 1.95。
