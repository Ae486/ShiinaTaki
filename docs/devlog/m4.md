## #15 — 逐像素点击穿透（2026-07-14）

**结论：项目最高风险模块落地——小人不透明像素可交互、透明处穿透到底层。** 门禁全绿（desktop typecheck / lint / 21 前端测试 / -r typecheck / cargo build），check 零缺陷，坐标变换（最高风险行）经独立核实正确。零新 Rust（approach B）。

**破的核心难题——透明窗口悖论**：`setIgnoreCursorEvents(true)` 会杀掉所有指针事件、无法自己翻回（Tauri 官方 #2090/#6164 证实）。解法：从**全局 cursor**（`cursorPosition()`，Tauri 内建包 GetCursorPos）驱动 toggle，不依赖 window 事件。

**机制**：
- `renderer/alpha-mask.ts`（纯采样）+ `alpha-mask-source.ts`（每 painted 帧把 `app.stage`（identity=屏幕空间）渲进 ¼ 分辨率 RenderTexture 读回，挂 governed ticker，随 governor 节流）。cursor 轮询只读一格 O(1)，绝不 per-poll extract（=GPU stall）。
- `windows/pet/use-click-through.ts`（hook，唯一碰 Tauri）：~40Hz 轮询 `cursorPosition()` → 全局坐标转窗口本地（`(cursor−innerPosition)/scaleFactor`）→ 查 mask → `ignore = !dragging && !buttonDown && !opaque`，仅变化时切、busy 锁防 IPC 重叠、teardown 恢复交互。
- 拖拽 flag 提升到共享 `interaction-store`，拖拽期挂起穿透（不漏穿）；恢复被 OS 吞掉的 pointerup。

**自主决策（技术决策树，无产品/spec 取向）**：alpha=web 侧缓存 mask；事件流=全局 cursor 轮询 approach B（零 Rust，合不变量 1），延迟卡顿再回退 A；不加 windows crate（Tauri API 底层已设 WS_EX_TRANSPARENT）。顺带修正 TECH-STACK:43 夸大 crate 作用的表述。

**两处 sound deviation**（check 独立核实）：不用 `containsPoint` 粗筛（model-local bounds 喂屏幕坐标会误拒漏穿；mask 是 O(1) 唯一权威）；渲染 `app.stage` 而非 model（identity 变换=1:1 坐标映射，消歧义）。

**待人工验收**（manual-checks #40-45）：小人身上可交互、透明处穿透到底层、坐标对齐轮廓（关键失败模式）、随动画追踪、拖拽中不漏穿、HiDPI 缩放。

**质量流程**：research（悖论 + alpha 成本 + 事件流架构，全对 installed 源验证）→ 主脑自主裁定 alpha+B → implement（Opus）→ 主脑亲验（读核心 hook、复跑门禁、核 deviation）→ check（Opus，零缺陷，独立核坐标变换）→ 自主提交。
