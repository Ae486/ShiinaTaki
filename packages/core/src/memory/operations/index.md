# core/memory/operations/
The durable memory operation owner (Hindsight closure Stage 1, D-S1-1; Stage 2a local kinds): one Core-owned table + service
over the existing B3 setup service, B5 replica scheduler and the Local onboarding service. Outcomes are classified from what
those producers persisted; nothing here runs a second scheduler, recovery loop, or authority write.
- memory-operation-contract.ts — handler contract per kind (family/admit/persistAdmission with the Core-stamped origin/execute/observe/observeBoot/cancel), six mutually exclusive families, durable request lookup, settlement/observation and execution CAS seams
- memory-operation-kinds.ts — MEMORY_OPERATION_KINDS, the closed registry (one row per kind, hindsight.activate, bank.provision and connection.revalidate included) and the dispatch-boundary erasure helper
- memory-operation-kind-setup.ts — setup.validate / setup.apply: wrap HindsightSetupService, settle from the returned snapshot (failed phase => producer_failed; thrown refusal => producer_refused)
- memory-operation-kind-replica.ts — replica.sync: durable manual request + one awaited scheduler tick; classification from exact durable request/claim/outcome evidence, including boot without a live runtime; exact queued cancellation while another run holds the Bank; post-admission status/receipt read failure stays unresolved
- memory-operation-kind-transition.ts — operator-only transitions, both full admission plans over one transaction-local independent context, deferred claim/cancel and durable settlement; post-driver lookup/evidence errors remain unresolved
- memory-operation-transition-storage.ts — original/recovery request lookup, context-aware pure plan contract, atomic admission and receipt/failure-based live/boot observation; W5 supplies the healthy producer
- memory-operation-kind-local.ts — local.onboard.prepare (new/resume/retry) and local.onboard.activate: cheap synchronous admission, macrotask-deferred tryClaim CAS, producer checkpoints, settlement from run/receipt evidence, pre-claim cancel, read-only boot observation; an already-committed exact run repairs the binding only
- memory-operation-local-evidence.ts — local producer-ref constructors, closed MemoryLocalErrorCode mapping (never a replica code), and the prepared/committed/unknown/interrupted settlement builders
- memory-operation-kind-hindsight.ts — hindsight.activate (new/resume/recover): synchronous side-effect-free admission with Core-minted identities and the exclusive-family guard, macrotask-deferred tryClaim, chain checkpoints, settlement from the receipt and binding snapshot (activated / binding_unavailable / prerequisite_blocked), pre-claim cancel, read-only boot observation; recover repairs the binding only
- memory-operation-hindsight-evidence.ts — hindsight producer-ref minting/replay (per-Bank base verification ids), identity projection and the failed/unknown/completed/blocked/committed settlement builders
- memory-operation-kind-bank.ts — bank.provision: synchronous admission (runtime without drift, verified Global row, Bank not already ready, Core-stamped origin), deferred claim, phase checkpoints, ready -> completed / syncing or setup failure -> failed with the closed code, pre-claim cancel, boot observation from the B3 row + replica binding
- memory-operation-kind-connection.ts — connection.revalidate: admission on the exact selected epoch with before/after fingerprints, deferred claim, phase checkpoints, unchanged/rebound -> completed, binding_unavailable -> failed runtime_unavailable, pre-claim cancel, boot observation from the reviewed fingerprint + admission evidence + published runtime
- memory-operation-kind-backup.ts — HINDSIGHT_BACKUP_FAMILY and the helpers the three backup kinds share: required producer, marker-epoch admission, deferred claim, outcome -> settlement, restart settlement, pre-claim cancel
- memory-operation-kind-backup-admit.ts — backup.admit: admission (producer, Hindsight marker at the expected epoch, exclusive-family guard) carrying the staged backup id; boot observation settles a sealed pair completed or hands a claimed ZIP back as outcome_unknown
- memory-operation-kind-backup-verify.ts — backup.verify: admission (producer, Hindsight marker, exclusive-family guard), settlement from the verify outcome, restart as outcome_unknown
- memory-operation-backup-fixtures.ts — test support (not in the production path): mirroring native route, activated journey, refusal and open-row helpers for the backup kind journeys
- memory-operation-kind-backup-capture.ts — backup.capture (route c native-endpoint by default, route b operator-artifact stages the Core half): synchronous admission (backup producer, Hindsight marker at the expected epoch, runtime without drift, exclusive-family guard) minting the backup id, deferred claim, phase checkpoints, settlement from the capture outcome (pair mismatch carried in the result), pre-claim cancel, boot observation that quarantines the partial dir as outcome_unknown / producer_incomplete
- memory-operation-lifecycle-settlement.ts — hindsight-lifecycle family helpers: required service, deferred claim, closed code -> reason mapping and settlement builders
- memory-operation-service.ts — one operation owner: per-kind boot reconciliation, single-flight atomic admission with fresh transition-only evidence scope and entry timestamp, detached execution, observed CAS settlement/cancel, fan-out and bounded stop; shared execution context never retains admission proof/time
- memory-authority-status.ts — readMemoryAuthorityStatus: the composite memory.authority.status read (authority marker, runtime availability with closed reason from the Hindsight binding snapshot/probe or the Local binding snapshot — connection_disabled/config_changed separate from authority_mismatch — setup, per-Bank replica + Pending/parent-write counts, active/recent operations, the `hindsight` lifecycle section fed with open bank.provision Characters, exclusive-family business, the lifecycle revalidate blocker and the backup block, an unreadable live connection read as unconfigured, derivedFreshness "unknown")
- memory-hindsight-lifecycle-status.ts — readHindsightLifecycleStatus: the pure `hindsight` section (live config vs runtime vs B3 fingerprint drift, stored admission time, per-scope Bank readiness from B3 rows, replica checkpoints, open lifecycle operations and Timeline Characters, Core-derived actions: revalidate on drift or a repairable unavailable runtime unless the revalidate blocker refuses, provision for unprovisioned/failed Characters while the runtime serves, none while an exclusive family is open; the backup block as read)
- memory-operation-fixtures.ts — test support (not in the production path): fake scheduler/runtime/setup doubles and the legal Hindsight authority marker seed
