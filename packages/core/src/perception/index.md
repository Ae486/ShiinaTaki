# core/perception/
- perception-layer.ts — single ambient/privacy composition; wires accepted activity, scheduling and pause producers to opt-in invalidation before sampling starts; serves the existing card and retires change/deadline observation at Core shutdown
- perception-changes.ts — process-local invalidation owner and one unref'd absolute pause projection deadline while operator interest exists; lazy state reads only, with replacement/expiry/close/shutdown guards and no mutation/capture/model path
- perception-subscriptions.ts — authenticated operator connection Map, idempotent setup, first/last interest transitions and isolated content-free fan-out; no unsolicited snapshots
- notify-perception-change.ts — data-free observer isolation shared by source producers; observer failures cannot change committed source outcomes or log private error content
- ambient-screenshot-sampler.ts — the DEFAULT-OFF ambient screen poll: enable flag decides scheduling, then per tick pause → the cheap pre-filter over T3a's recorded entry (known+fresh+non-sensitive; a sensitive app makes it UNKNOWN, because T3a seals the state) → window changed or refresh due → the FINAL fresh foreground screen (foreground-screen.ts) → route `screenshot-ambient` (its own grant) → save → VLM describe (carrying the sensitive-screen privacy focus; a sensitive verdict discards the frame whatever the retention config, keeps the previous observation and logs nothing identifying) → PII scrub → screen context; DENIED (of either capability) stops the session, no vision slot logs once and stays off; never throws
- foreground-screen.ts — the FINAL pre-capture gate: one fresh `foreground-window` route immediately before the capture, so the decision rests on what is in front NOW and not on an entry that is one poll old by construction (D48's residual is then a single round-trip, not a poll interval); fail-closed on every unreadable shape, names nothing in its verdict, and owns the shared scrubbed foreground identity rule
- sensitive-screen.ts — privacy layer TWO: the ambient describe call's privacy instruction (reply `SENSITIVE_SCREEN` instead of describing a credential / payment / private-message / login surface) + the fail-closed verdict test that is deliberately more forgiving than the prompt; covers what an exe-name skip structurally cannot see (inside a browser)
- perception-card.ts — the human-facing status card behind `perception.card` ({ current, recent, samplingStatus, pauseState }); reads the same in-memory activity state, no fence (nothing here enters a prompt)
- screen-context.ts — the bounded (latest-only) ambient screen observation + its fenced renderer; a stale observation stops rendering, so a paused/stopped sampler bleeds out of the prompt instead of lingering
- ambient-shot-store.ts — the sanctioned write site for AMBIENT frames: its own directory + its own filename shape, so discard/sweep can never reach an on-demand capture or any foreign file; a failed write degrades to null
- ambient-shot-gc.ts — retention ENFORCEMENT policy honoring keep / N-days / drop-after-describe (the inline drop's crash backstop); runs regardless of the enable flag, on the shared scheduler/sweep-runner schedule
- privacy-pause.ts — Core-owned durable ambient consent; factory hydration and timer-free absolute-deadline reads; successful changed writes notify only after persistence, with perception.pauseSet remaining the sole production mutator caller
- sensitive-processes.ts — conservative built-in skip list (only entries a comparable names explicitly) + operator extras, exact case-folded match on the normalized app/exe name; documented gap: it cannot see inside a browser (incognito is still chrome.exe)
- pii-scrub.ts — deterministic regex scrub applied at the sense seam BEFORE fencing and before storage: vendor-prefixed secrets, JWT, PEM private keys, URL/DB credentials, email, E.164 phone, Luhn-checked cards, mod-97 IBANs; pure, no model, no opt-out
