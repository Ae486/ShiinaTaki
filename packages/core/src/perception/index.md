# core/perception/
- perception-layer.ts — single ambient/privacy composition; retires observation epochs and cached dwell/screen only after durable consent commits; wires accepted evidence, source lifecycle and opt-in card invalidation
- perception-evidence.ts — process-local observation epochs, nullable session-idle evidence and continuous application facts with the actual Host/connection/catalog binding; no operator-device association
- foreground-continuity.ts — bounded title-free application occurrence and dwell derived only from consecutive accepted same-source samples; idle/unknown changes, gaps and retirement break continuity
- perception-changes.ts — process-local invalidations with synchronous compound-retirement batching and one unref'd interested-operator pause deadline; no mutation/capture/model path
- perception-subscriptions.ts — authenticated operator connection Map, idempotent setup, first/last interest transitions and isolated content-free fan-out; no unsolicited snapshots
- notify-perception-change.ts — data-free observer isolation shared by source producers; observer failures cannot change committed source outcomes or log private error content
- ambient-screenshot-sampler.ts — DEFAULT-OFF cadence with cheap current-foreground filter, fresh screening, Host-pinned screenshot dispatch and consent/source checks after every await; retirement resets refresh suppression; either capability denial stops the session
- ambient-observation.ts — native pending-frame publication under the original consent/Host predicate; protects live files from GC, releases producer sidecars and discards withdrawals under all retention modes
- foreground-screen.ts — the FINAL pre-capture gate: one fresh `foreground-window` route immediately before the capture, so the decision rests on what is in front NOW and not on an entry that is one poll old by construction (D48's residual is then a single round-trip, not a poll interval); fail-closed on every unreadable shape, names nothing in its verdict, and owns the shared scrubbed foreground identity rule
- perception-card.ts — the human-facing status card behind `perception.card` ({ current, recent, samplingStatus, pauseState }); reads the same in-memory activity state, no fence (nothing here enters a prompt)
- screen-context.ts — one latest native frame, metadata-only renderer and once-per-Attempt acquisition; expiry/replacement/withdrawal invalidate pending and in-use pixels
- ambient-shot-store.ts — the sanctioned write site for AMBIENT frames: its own directory + its collision-free filename shape, cross-instance protection and isolated discard/sweep; a failed write degrades to null
- ambient-shot-gc.ts — retention ENFORCEMENT policy honoring keep / N-days / drop-after-consumption (protected pending/in-use frames survive sweeping); runs regardless of the enable flag, on the shared scheduler/sweep-runner schedule
- privacy-pause.ts — Core-owned durable ambient consent; factory hydration and timer-free absolute-deadline reads; successful changed writes notify only after persistence, with perception.pauseSet remaining the sole production mutator caller
- sensitive-processes.ts — conservative built-in skip list (only entries a comparable names explicitly) + operator extras, exact case-folded match on the normalized app/exe name; documented gap: it cannot see inside a browser (incognito is still chrome.exe)
- pii-scrub.ts — deterministic regex scrub applied at the sense seam BEFORE fencing and before storage: vendor-prefixed secrets, JWT, PEM private keys, URL/DB credentials, email, E.164 phone, Luhn-checked cards, mod-97 IBANs; pure, no model, no opt-out
- browser-playback-sources.ts — bounded paired-Host browser sources with socket/catalog provenance, attachment tombstones, expiry and privacy retirement; no inference or acceptance
